# 项目特有代码模式

> 项目里**反直觉、容易踩坑、需要特定写法**的模式。AI 实现新功能前 Read 一遍。
>
> 本文件为**模板**，按项目实际填充。记「项目特有的」，不记通用语言 / 框架知识。

## 何时补充本文件

- 实现新功能时发现「这里有非显而易见的约定」
- 修 bug 时发现「这套用法是有原因的，下次别改」
- 做出「以后所有 X 都按这种写法」的统一决策
- 发现项目里隐藏的「地雷」（容易踩坑的写法）

## 不要写什么

- 通用语言 / 框架知识（那是官方文档的事）
- 显然的命名规范（在项目根 `CLAUDE.md` 里写）
- 一次性的实现细节（在源码里看就行）

## 格式模板

```markdown
## <模式标题>

**适用场景**：什么时候要用这个模式

**做法**：
\`\`\`<lang>
// 简短示例
\`\`\`

**为什么** / **替代方案为什么不行**：......

**对应位置**：`path/to/yyy.<ext>:NN`（参考实现）
```
