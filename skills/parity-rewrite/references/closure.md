# 行为出口闭包：五类出口的强制遍历

> 本文件为 parity-rewrite skill 机制条文，SKILL.md 执行到〔第 0 步第 6 条、铁律 10、Phase 1 Step 1/2/3、Phase 2 定稿 = Human Gate〕时 Read 本文件。

## 行为出口五类总则

**行为出口 = 模块内一切产生可观察行为的发生点**，分五类，按模块**实有类**逐类反查——①弹层出口（弹窗树，本文件下文全文）②状态转移 ③外设副作用出口 ④本地持久化写点 ⑤定时/延时事件。通用纪律：每类反查法同根（**入口机械化——反查调用点/写入点/注册点，wrapper 命中则迭代并入至集合不再增长**）；**模块无某类 → 显式负证据行「本模块无此类出口（查过于:___）」，不许默认无**；各类出口形制（弹层栈/状态字段形态/外设服务栈/持久化 API/定时器注册点）由**适配节登记**（「行为出口形制清单」），第 0 步现场查得回填；**双侧各查各的**原则（下文）适用于五类，不只弹层。

- **② 状态转移闭包**：遍历对象 = 模块**自有**的状态字段/状态机（订单/账单/支付/挂单类；服务端下发态值归清单第 1 节字段值域，其消费分支仍由功能×分支态覆盖，不入此列）。起点清单 = 状态枚举成员全集；反查 = 状态写入点/转移方法调用点（wrapper 迭代同法）。**完整性判据（本类特有）：状态枚举每个成员必须作为某条转移的源或目标至少出现一行**——成员无行 = 漏转移，直接红。每行登记：源态→目标态、触发点、守卫条件、连带副作用（交叉引①③④类行号）；落清单第 10 节
- **③ 外设副作用出口闭包**：遍历对象 = 离开模块边界、驱动外部设备的**输出侧**发生点（打印、秤、扫码枪配置、钱箱、客显等；扫码/键盘等**输入侧**事件归⑤隐性事件源，两侧不混）。反查 = 外设服务 API/平台通道调用点，wrapper 迭代同法。每个出口一行：设备类、触发点、载荷关键内容（如打印模板要素）、失败分支；并入清单第 2 节同表（「关联接口」列填外设服务 API）
- **④ 本地持久化写点闭包**：遍历对象 = 本地库/缓存/偏好存储的**写入点**（读点随第 1 节数据面对齐）。反查 = 持久化 API 调用点；并入清单第 1 节同表（「接口/命令」列填持久化 API+目的表/键），不另立节
- **⑤ 定时/延时事件**：机制并入下文①类「隐性事件源同查」条——形制清单补 Timer/延时任务/轮询注册点（自动刷新、超时弹窗、轮询重连），反查形制补定时器注册点，核不到须有「查过于:___」行

## 弹窗树：嵌套弹层的强制遍历（①类）

**病灶（①类弹层出口，复刻实战采证，需求方确认）**：二三级弹窗经常不被读——Step 3/4 遍历对象是「page → 下一个功能页面」，弹窗/面板/抽屉是 modal 不是 page，在枚举模型里没有位置，AI 自然不会去读；漏网的弹窗行为在验收或上线后暴露，即返工。

## 出口闭包规则

入口机械化——不靠"看代码想起来"，反查弹出口调用点。**起点清单**：`showDialog` / `showModalBottomSheet` / `showGeneralDialog` / `showMenu` / Cupertino 系弹窗 / 自定义 overlay / 面板展开态 / 路由 push 的弹层页；**栈形制由第 0 步按项目实际扩展**（零项目值不破）。关键堵漏：**若弹出口命中项目封装（wrapper），必须识别封装体 → 把封装体的全部调用点并入出口集 → 迭代至集合不再增长**——只 grep 原生 API 会在"最大弹出面走 wrapper"的工程上当场复发漏读。**wrapper 机械判据**（防"算不算封装"又成交付语义自判）：函数体内含原生出口**或已认定 wrapper** 调用的项目自有函数/方法，即并入，按 grep 函数体递归判定，不按命名风格或观感。每个出口 = 树的一个节点

## 双侧出口集，各查各的

树枚举反查的是**参照实现侧**的闭包（其栈形制记入适配节「参照实现行为出口形制清单」（五类），第 0 步现场查得）；「防外溢闸」的复用面 / 引用方回归（[boundary-asset.md](boundary-asset.md)）按**目标工程侧**闭包计。两侧"查过于:___"分开留痕。事件总线式二阶间接（非方法调用直链）机械不可达，显式归返工账兜底（[rework-ledger.md](rework-ledger.md)）——事件源形制清单是启发式非完备，剩余漏网归返工账根因「枚举漏」回灌。双侧原则适用于五类出口，不只弹层

## 隐性事件源同查

树节点除"看得见按钮的弹层"外，还须登记**事件驱动弹出**——socket/推送消息触发的弹窗、扫码/键盘等外设事件（输入侧）、全局 redirect/guard、定时/延时事件（Timer/延时任务/轮询注册点，即五类之⑤）。反查形制：全局监听注册点 + 消息路由表 + 定时器注册点；核不到的工程显式记"本栈无此类源（查过于:___）"，不许默认无

## 父子链与节点登记

每节点登记**父子链**（二级弹窗 ← 一级弹窗哪个按钮/条件唤起）与自己的四列：功能×分支态、文案点、视觉关键值、对照断言（模板〔页面-弹窗树清单〕树化；〔下游页面清单〕保留为**页面间下游跳转**清单，弹层进树、页面跳转进〔下游页面清单〕，两节不重不漏）

## 完整性单一判据

**「本批作用域内五类出口闭包完整（实有类逐类；状态类另加枚举成员全员出现）」= 可定稿**——批次分片合法，但作用域外的出口/子树必须在清单显式登记为「待后续批次」行（算已填，不算空格）。**作用域怎么划**（防定稿先于分片的时序矛盾）：作用域=本任务 Phase 3 分批的**首批「改哪里」范围 + 适配节预划模块边界**，在 **Phase 1 开始前划定并登记在清单头部**（不是定稿时才有）；后续批次各自定稿前重划。**本判据为全篇唯一表述**——SKILL.md 铁律 10 与 Phase 2 定稿闸均引此处，各处不得另立表述

## 跨批销账

「分片合法」的正当性前提：任一后批定稿包必须**出示前批全部「待后续批次」行的销账核对**（逐条：已枚举→转正式行 / 确属范围外→新登记归后续批），任务终收口（Phase 5）时核销账率——不许烂尾
