# 网络通信（MQTT / 消息推送）

> 触发场景：接入 / 调试 MQTT 等消息通道、编写断线重连 / 订阅逻辑、推送到达性排障前 Read 本文件。

> 归属：网络层消息通道坑（连接生命周期 / 订阅与 QoS / 到达性 / broker 配置安全）住本文件；设备 / 外设通信住 `references/iot-devices.md`（互留指针）；OS / SDK 平台坑住 `references/platform-pitfalls.md`。
> 锚口径：commit 哈希为 saas-cashier 私有仓锚（采证线 2026-09-24 全量 cat-file + merge-base 核验）；`doc/…` 为其仓工作树案卷文档。broker 凭据 / 实例名 / 域名 / 门店与订单标识全脱敏，机制层照常成立。
> 主题结构（隔离模型）：`{环境前缀}/{print|order|takeout|goods|callNumber}/{cashierId}`——店级隔离全押 topic 内的身份段（SP 持久设备身份），消息实体本身无店 / 设备字段；QoS 双轨：print / takeout = atLeastOnce，order / goods / callNumber = atMostOnce。

## 连接生命周期

**重连成功 ≠ 订阅还在：重连订阅走「双路径」，间接补订链三处可断（本域头号坑）**——症状：断线自动重连后部分 topic 静默收不到推送，实证事故即 print topic 全店收不到单（云打印不出票）。机制：重连成功回调里仅 print 直订（atLeastOnce），其余四个业务 topic 先退订、再依赖「退订成功回调」补订；该间接链三处可断——① 退订前置「连接态=connected」不满足时退订直接跳过、回调永不来；② 登出态窗口内补订被守卫拦截；③ 补订失败仅回调再试、无退避无上限。任一环节断 → 该 topic 失订且无对账告警。演化史：引入分支（bd23e3d71 2024-08-23）→ print 移出退订清单（ed8d8ec5c 2025-06-10，此后两天 print 重连**既不退订也不重订**、订阅存续完全押 broker 会话，会话丢失即失订——打印丢失事故码面窗口）→ print 直订补上（12365c95a 2025-06-12，仅 +1 行）。终态现状：print 已修，**其余四 topic 仍走回调链**。修法方向：重连分支直接全量显式重订（broker 对已订 topic 重复 SUBSCRIBE 幂等），废除「退订→回调→补订」链。锚：12365c95a、ed8d8ec5c、bd23e3d71、1a3d6b646。

**库级自动重连禁用，手写定时器重连（20s / 5 次熔断 / 1 分钟休眠）**——mqtt_client 的 autoReconnect / resubscribeOnAutoReconnect 全家注释禁用（6492ba793）——库级「重连+补订」整套放弃，断线感知靠断开回调拉手写定时器：固定 20s、连续 5 次失败熔断停 1 分钟归零重试、maxConnectionAttempts=1。指数退避曾引入生效（4768f70c6：1s 起步 clamp 上限 30s）后被注释改回固定 20s（a6a580895）——间隔演化链 20000→6000→7000→指数退避→20000 五跳。坑面：熔断后 1 分钟休眠窗口推送全丢（无补偿，见 QoS 卡）；重连后的订阅恢复全靠手写路径（见上卡）——**禁用库级自动重连 = 把重连+补订完整责任接过来**，不是省事。锚：6492ba793、4768f70c6、a6a580895、665f39131。

**单例语义与同 clientId 互踢**——clientId = 固定前缀@@@cashierId：同店同身份双开 / 重复登录即互踢（broker 同标识拒绝并存，代码注释自证）；历史互抢链接修复（b6042cddd）→ 单例化改造 + 登录防抖（fffe5631f 2024-04-09）→ 连接前状态双守卫防重复 connect（6b823d86b）→ 重复订阅修复（a811fdddd）。残余：订阅成功清单只增不去重、实例重建才清空（功能无害，观察项）。教训：clientId 是全局唯一资源，登录 / 切换设计把「同标识互踢」当第一约束。锚：fffe5631f、b6042cddd、6b823d86b、a811fdddd。

**登录 / 登出 / 切店与连接生命周期耦合**——登出有完整退订+断连+实例置空链；踢出登录双通道：print topic 的 JWT_KO 码只记日志、实际踢出靠 HTTP 层同码 + 叫号 topic 的 kickOutLogin 码（踢出断连 / 防重复 / 断连报错多笔修复史）。切店：topic 与 clientId 都拼 cashierId（SP 持久值）——「先存新 id、延迟 2s 重连」是纯时序约定，旧 topic 订阅残留即串台（服务端仍向旧 id 投递）；曾修 topic 从 getter 变 method 保证取现值（d7b2cc979）。前后台切换**无任何**重连 / 重订分支（全量 grep 零命中，如实登记）——OS 杀进程靠冷启动登录链重建，仅前后台切换不触发。锚：d7b2cc979、b9cb1cc11、b81d58421、61decc5f9、57438d71d、259cc8885。

**连接状态多处持有 + 「翻译后字符串」判状态：误红系列**——连接状态一处权威多处转手（manager 内部状态 → 全局 provider → Riverpod 与通用数据管理双消费者），断线感知靠库回调 + keepalive 兜底；连接监测编排器判「已就绪」用的是**翻译后文案字符串**（排除「连接中 / 未连接」多语言文案），换班登出残留态曾致误红。误红系列五笔修复史（首检须等 MQTT / 断开立即标红不走去抖 / recheck 快照与 provider 不同步 / 残留态）。教训：状态判定永远用枚举原值，文案字符串只管显示；跨持有方读取过 provider 单一出口。锚：8ef704d90、b9ba9af5b、791dc311a、bfa125823、ed332902d。

**心跳 / 超时参数现值（接入自检表）**——keepalive 20s；无响应断开 30s（注释实证 ping 后 15s 收强制断开回调）；连接超时 15s（曾默认 5s）；重连 20s / 5 次 / 1 分钟（见上）；心跳 ping/pong 回调曾**错线接反**（pongCallback 接了 ping 处理器、pingCallback 未接 → 心跳时间戳恒不更新，ec7299dcf 修正）——回调接线对着库源码核。依赖 mqtt_client 10.3.0（曾升 10.5.x 后回退）。锚：ec7299dcf、a6a580895、19c2c8d84、cc5060437、648faba65。

## 订阅与 QoS

**QoS 双轨 + 下行无对账：订阅成功 ≠ 推送到达（外卖新单无声案实证）**——五业务 topic 仅 print / takeout 是 atLeastOnce，order / goods / callNumber 全 atMostOnce（订阅函数逐字核验）；发送侧写死 atLeastOnce 但客户端零发布调用方（纯消费）。下行侧无任何对账 / 补偿（无 seq / ack / 重拉）；离线补拉能力历史上线过又**整体回退一次**（发布日志 v2.4.8/2.4.9 → v2.4.10 回退 → v2.5.1 重新落地）。实证案卷：某烘焙商户门店外卖主题订阅成功、对照组主题秒级正常、外卖主题全窗口 **0 条推送到达** → 自动接单无声；客户端定位完成（触发源缺失不播），待服务端协查。教训：「订阅成功、回调正常」与「推送到达」是两件事——atMostOnce 主题断线窗口消息直接丢，atLeastOnce 也只保证至少到一次客户端（服务端未下发仍为 0）。排障纪律：先取证到达层日志（引擎对非 print 推送全量落日志）再查消费层。锚：a547410d5；doc/takeaway_auto_accept_no_voice_case_report.md、doc/2.10.6_问题统计分析.md（工作树案卷）。

**分发面：EventBus 单监听 5 消费方 + 批量帧只取第一条**——引擎转实体后经全局事件总线分发，全仓恰 5 个监听方（桌台 / 叫号大屏 / 快餐菜品 / 外卖列表 / KDS 转发），全部只按主题字符串过滤、无二次按店 / 按设备过滤——隔离完全押 topic 身份段（见切店卡串台）。结构隐患：库回调载荷是消息列表、分发只取第一条 → 同批多条丢尾（曾修「stream 已关后 add 报错」重构加三层校验但保留取首条；无实证事故，观察项）；实体仅主题+内容两字段，消费者要做二次隔离也没有原料。锚：8c7299cbe；现行代码。

**叫号 topic 未知 code：静默丢弃 + 误导日志（现行缺陷，接入前自查）**——分发器按 code 白名单逐码 if/else 赋值 `late` 实体变量，白名单外新码不赋值直接 fire → LateInitializationError 被 catch 吞掉、日志写「EventBus fire 异常，可能是 stream 已关闭」——**报错方向完全误导**（真因：服务端新增码未登记）；服务端在叫号主题新增任意业务码，客户端每条丢且查错方向。同类第三条丢弃路径：消息入口前置登录态 / 连接态双静默 return。纪律：code 分发禁 late+逐码 if/else 结构；未匹配码走 default 留日志降级不丢。锚：现行代码（mqtt_engine.dart 分发段，接入前自查）。

## 业务到达性案卷（推送到了之后 / 到不了）

**推送到达但「找不到打印机」：身份未就绪窗口**——症状：打印推送到达客户端却找不到对应打印机，制作单丢失。机制：topic 拼设备身份（SP 持久），打印机列表按当前绑定身份过滤，身份落库与列表拉取非原子 → 窗口内推送到了、列表空或不含该打印机。修法：绑定完成后 await 列表落地（两处：等待列表 + 放开刷新前置）。与头号坑合看：「重连成功≠订阅还在」与「推送到了≠身份就绪」是打印丢失的两个半边——下行排查必须分层取证。锚：693904bbb。

**服务端重推 → 同单多次打印：客户端有界去重兜底**——服务端以「未收到打印成功回复」为重推依据（QoS1 至少一次 + 服务端无到达对账），同一制作单多次打印（提交体原文工单语义）。修法：printId 有界去重队列（容量 100、满挤首、命中跳过；现行落点 printer_manager.dart）。残余坑：窗口仅最近 100 条、跨重启清零——重推间隔超窗口或客户端重启即复发；客户端队列只是兜底，根治在服务端到达对账。与叫号去重卡同族：**重复消费修复都是客户端有界兜底**。锚：cb1c6fe95。

**叫号制作中推送重复入列**——同一订单在「制作中」列表重复出现。修法两笔：列表 logic 按订单号存在性去重（9d8827094）+ 直连调用改事件广播各列表自订（5b37f6375，消灭「logic 未注册时强取单例抛错」）。残余：列表先清空重建可绕过去重（重建与推送竞态）；叫号主题 atMostOnce 丢推无重投、TV 断连时转发静默丢弃无留痕。锚：9d8827094、5b37f6375、131cb07d0。

**大屏 / 叫号 TV 跨店串台：按店隔离 key 自引入日从未生效（现行缺陷，修复在支线）**——症状：换店登录后收银机自动连上前一家店缓存的叫号 TV，叫号播到别家店。机制：设备缓存 key 拼店 id 的赋值放在 logic 初始化段——而该 logic 冷启动即全局常驻注册（早于登录、店信息为 null）→ key 恒为「空店号后缀」，按店隔离自引入日（04b82bcbc 2024-04-20）从未生效；现行缺陷在位（主线初始化原文未动）。修复（key 动态按当前店计算 + 登录后恢复 + 登出断连防复活 + 存量迁移）在支线未并主线（2d11e59ef，merge-base 实证 NOT-on 采证线）。教训：**全局常驻 logic 的初始化段读不到「晚到的上下文」**（登录态 / 店信息）——按身份隔离的 key 必须动态取或延后到身份就绪后固化。接入大屏 / 叫号 TV 前必查此点。锚：04b82bcbc；支线 2d11e59ef、d0f003d5c。

**优惠付款码到账播报：寄生迁移史 + 寄宿 atMostOnce 主题（现行缺陷面）**——顾客扫优惠付款码付款 → 主收银机播报到账金额；寄宿叫号大屏 logic（注释自认「暂时放这里，该播报不依赖任何界面」，由全局常驻注册兜住「不依赖界面」）。四坑：① 主题寄生史——handler 曾落外卖 logic 吃外卖主题（ed65f8b22），后迁叫号主题 + 白名单加码（37b30b018）——曾与外卖主题共存亡（QoS 卡案卷若发生在迁移前，到账播报同灶死亡）；② 叫号主题 atMostOnce、丢推无重投无对账 → 到账不播无痕；③ 双开关且默认关（渠道门 + 开关 defValue false，未显式开启即静默）；④ 白名单脆弱（见未知码卡）。教训：临时功能寄宿生产链路 = 四面暴露；新播报类型独立评估主题 / QoS / 开关三件套。锚：7178aa9b2、ed65f8b22、37b30b018。

## broker 配置与安全

**broker 配置安全面（机制层，接入前自查清单）**——四坑全部现行（凭据 / 实例名 / 域名已脱敏不进仓）：① 三套环境 broker 凭据（key/secret 对）明文硬编码常量文件、随包分发——移动端硬编码凭据可被逆向提取，应走下发或至少最小权限+可轮换；② 明文 TCP 1883、TLS 默认关；且 TLS 开关旁证书校验回调**全放行**（onBadCertificate => true）——开了加密不等于验了身份；③ 初始化日志明文打印密码（进日志流）——日志脱敏红线；④ 实例迁移史三笔（测试 / 生产 / 域名切换）说明凭据轮换是现实常态——硬编码状态下每次轮换都是发版级操作。接入 MQTT 逐项自查：凭据存放 / 传输加密 / 证书校验 / 日志脱敏。锚：0a6905bd5、5ac9d00ed、796b67d75；现行代码。
