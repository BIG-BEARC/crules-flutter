**定性观察**：
- 新版三题**全部正确按域路由**（骨架→design-doc.md、坑库→platform-pitfalls.md、主题→theming.md），薄索引的 references 指引无一漏读——「多一跳检索」未造成任何断言失败
- 浓缩版 theming.md 的 lerp/copyWith 全例被正确复用——浓缩未伤 API 完整性
- 两版产出质量互有妙笔（新版骨架题引用了坑库两卡做平台矩阵；旧版主题题主动修正了 skill 基线样例的可空字段写法）——差异属模型随机性范畴，非 skill 版本效应

## 3 诚实声明

1. **每配置单次运行**——方向性证据，非统计结论（无方差可报）
2. 对照组是**旧版 skill 快照**而非「无 skill」——本评测只回答「拆分是否伤」，不回答「skill 本身是否值」
3. 断言 2 初版要求字样「三方依赖」两版同挂（报告用坑卡同义「插件层/引擎层」表述）——修正为语义等价集后双绿；**断言过字面**是本次评测自身的方法论教训
4. 任务通知的 token 计数口径异常（141s/7 工具调用报 430），不具可比性，未采信
5. 子代理无法访问消费工程的 CLAUDE.md §七——两版同受此限，不影响对照结论

## 4 结论

B1 中档拆分**验收通过**：内容可达性无损、按域路由可靠、附带 ~17% 提速、触发载荷 −89%。坑库独立成 skill（③档）的既有裁决维持——等 B3 常驻观测数据再议。

## 5 附：description 触发优化循环记录（2026-09-05 · 不采纳）

- **设置**：20 条查询（10 应触 + 10 near-miss 不应触），12 训练 / 8 保留，每查询 3 次采样，skill-creator `run_loop`（模型 glm-5.3），最多 5 轮、按保留集分选优
- **结果**（3/5 轮后止损终止）：

| 轮 | description | Train | Test（保留集） |
|---|---|---|---|
| 1 | 现版（0.5.0 拆分后） | 19/36 · P100% / R6% | 12/24 · **R0%** |
| 2 | AI 候选（枚举式+显式排除） | 17/36 · P0% | 13/24 · **R8%** |
| 3 | AI 候选 | 19/36 · P100% / R6% | 12/24 · **R0%**（与轮 1 完全同分） |

- **判定**：三轮 recall 钉死 0–8% 地板、轮 3 与轮 1 同分 = 在噪声上迭代，无收敛——**所有候选不采纳，保留现版 description**
- **根因**（评测设计问题，非 skill 问题）：①应触查询多为「一行问答」型（对比度多少 / Expanded 怎么选）——模型凭内化知识直答、不咨询任何 skill，系文档化现象（「Claude 只在任务无法独立完成时才咨询 skill」）；②precision 100% 恰是「几乎不触发」的另一面，非优点。**对照证据**：§1–2 的 A/B 子代理在「查规范出文档」语境下 6/6 正确读取本 skill，真实消费触发正常
- **教训**：参考库型 skill 的触发评估，应触查询必须是**多步实质任务**（如「审这份 PR 的主题与布局合规性并出报告」），一行问答测不出咨询行为
- **重测条件**（可选，未排期）：按上述教训重写查询集后再跑一轮；或等真实试点期的 skill 出场频率观测（README 维护节既有观测项）替代实验室触发测试
