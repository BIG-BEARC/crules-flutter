## 1 目标与范围

**要解决**：双模板 / 多文件间的「逐字同文块」目前靠**人肉同源对照改 + 机械检测**（test-self 断言）维持。机制数增加 → 断言数线性增长（现 27 断言中约 10 条为文档孪生守护）；且检测在追着漂移跑（「守串不守文」已吃过一次亏）。

**做法**：把**逐字同文块**从「多处副本 + 检测」改为「**单一源 + 生成 + 生成幂等断言 + 注入计数守卫**」——防漂移从**检测**前移到**构造**。

**做什么**：四块（✅ 亲验，边界**以 test-self 现有 awk/grep 的真实切片为准**——见各块括注）：
1. **档位预设节**（`### 档位预设` 至下一 `^###`/`^##`，**标题行含在块内**；`tp_sect` 断言本身 `next` 跳过标题行，不冲突）——app / plugin 双模板
2. **收尾时序行**（`^> 收尾时序`，单行）——双模板
3. **Gate 例外段**（`^例外一律落` 起，**至第二个空行**终止；实测切片含「正文 + 空行 + `---` 分隔线」，app:124-126 / plugin:117-119）——双模板
4. **help↔README 档位说明段**（`收尾档按任务规模三档判定` 所在行，**单行即整段**：help.md:26 / README.md:66）——commands/help.md + README.md

> **边界口径校正（R3/R4）**：第 3 块的终止条件是**第二个**空行（非「至空行」）；第 4 块现有断言用 `grep -m1` 只钉**单行**，「段」的名称失真——其**起止由本方案新定义**（非沿用既有断言），canonical 文件范围与该单行口径对齐写死。

**不做什么**：
- ❌ **不做全量**（实证依据，R10 补）：两模板 651 行中 **207 行逐字相同**，而被现有断言守护的仅 **3 段**——其余约 200 行是**偶然**同文的散落散文，拉进 byte 互锁即**禁止合法分化**。这才是「全量是幻觉」的真实依据（非仅「生成本就无法表达」）
- ❌ 不改任何**行为**（纯维护者面机制，消费面无感）

**消费方边界（R1 消解）**：第 1 块**是消费方 init 要编辑的**（`### 档位预设（init 选一，删未选两段…）` 自带编辑指令，`commands/init.md:44` 明令删减）。生成只保证**双模板初态一致**；**消费方拿到后可自由删减未选段**——围栏文案须区分受众（见 D2），不与 init 引导冲突。

## 2 核心决策

- **D1 ✅ 单一源放本仓 `canonical/`（不落消费方项目）**（R6 修正）：install.sh 为固定清单不复制该目录（✅ `install.sh:84-85`）；**但 plugin cache 是全仓库快照**（✅ `release.sh:8` 自述「cache 是全仓库快照（含 README/docs/scripts）」）——canonical/ 进 git 即进 cache。**措辞改正**：旧稿「源不随分发面走」不成立；实际是「不落消费方项目，cache 带源副本（惰性文件，无功能影响）」
- **D2 ✅ 标记围栏 `<!-- gen:<id> -->` … `<!-- /gen:<id> -->`，文案区分受众**（R1 消解；**R17 修正归属**）：说明行写作「**仓内维护者勿手改**（本块由 `canonical/` 生成）；**消费方按 init 引导删减未选段**」——双重受众一句内说清，避免落进消费方项目后与 init 指令冲突（✅ 复审核实：该分句显式让位于 `init.md:44`，同向不互斥）。**归属修正**：说明行**纳入 canonical 文件**（作为其首行）——围栏之间**全部内容**由 canonical 生成；围栏标记本身（`<!-- gen:… -->` 两行）手写在目标文件、不参与生成（原设计把说明行写死在围栏内，与「整块替换」语义冲突，首轮 render 即抹除——R17）
- **D3 ❓ render 走**编辑流**（改 canonical 后立即跑），**不进 release.sh**：守「bump 最后跑、cache 是全仓快照」纪律
- **D4 ✅ 试点期保留既有 byte 互锁断言（双保险）**：跑稳 2 个 minor 后再删——可逆迁移；**删旧断言的前置条件 = 注入计数守卫（D6）已就位**（R2）
- **D5 ✅ 脚本语言 python3**（R7 修正：旧稿 §4 验收命令误用 `bash` 跑 `.py`）
- **D6 ✅ 注入计数守卫**（R2 新增，防静默空转假绿）：render 对每个声明的 `(id, 目标文件)` 断言「恰好 1 对围栏 + 渲染结果与 canonical 同步」，任一不满足即**非零退出**——仓库既有同款先例 `test-self.sh:82-84` 的 `ran` 守卫（注释原文「防『没跑起来却空过』的假绿」）
- **D7 ✅ 「指针化」不适用（R11 论证留痕）**：先例 `twin:mem-files`/`twin:mem-trigger` 成立前提是**两份副本与指针目标同处一份交付物**；而 app/plugin 模板是**互斥交付**（`install.sh` 按 `--app`/`--plugin` 二选一，消费方只拿到一份，另一份不在场）→ 指针必悬空，**结构性不适用**。第 4 块指针化虽可行但不省（四方同源闸 `test-self.sh:132-151` 要求 README 字面含 8 个 gc 串，指针化会废掉该断言）
- **D8 ✅ 标题行归属**（R8 新增）：第 1 块 canonical 文件**含**标题行、围栏**包含**标题行（整块生成）——`tp_sect` 断言 `next` 跳过标题行，故不影响既有断言

## 4 目标方案

```text
canonical/                     ← 单一源（进 git；不落消费方项目，cache 会带源副本）
  gear-preset.md               → 双模板 §十二（含说明行 + 标题行 + 正文——围栏内全部）
  closing-tiers.md             → 双模板 §三「> 收尾时序」行
  gate-exception.md            → 双模板 §三 Gate 例外段（含尾随空行 + --- 写死）
  gear-note.md                 → help.md + README 档位说明段（单行口径）

scripts/render-blocks.py       ← 读 canonical/ → 按围栏注入（幂等 + 计数守卫）
```

**围栏示例**（**R17 修正**：围栏标记手写；**围栏之间全部**由 canonical 生成，说明行为 canonical 首行）：
```markdown
<!-- gen:gear-preset -->
<!-- 仓内维护者勿手改：本块由 canonical/gear-preset.md 生成；消费方按 init 引导删减未选段 -->
### 档位预设（init 选一，删未选两段；无块 = 默认标准）
…（标题与正文均来自 canonical/gear-preset.md）…
<!-- /gen:gear-preset -->
```
（第 2~4 行由 render 写入；首尾 `<!-- gen:… -->` 两行为**手写位置标记**，render 不改动）

**幂等 + 双守卫**（D6，R15 修正：补内容同步半句 + EXPECTED 改派生）：
```python
# 守卫① 登记一致性 + 计数：扫描四文件所有 `<!-- gen:` 标记，其 id 集合须 == EXPECTED 键集合
#   （堵「新增块忘登记」盲区——EXPECTED 不再是无守护的手工清单）；
#   且每个 (id, file) 恰好 1 对围栏，任一不满足 → exit 1（「没跑起来却空过」即红）
# 守卫② 内容同步：渲染后重读围栏区间字节，须 == canonical 对应文件内容
#   （堵「围栏在、内容却未改写」的残留假绿——旧稿只落计数半句）
# 渲染：围栏之间整块替换为 canonical 内容；重复执行产出恒等
```

**CI 断言**（R16 修正：**在 /tmp 副本渲染**——与原 R9 隔离口径自洽，不原地改写被跟踪文件）：
```bash
# test-self.sh 内：cp 四文件 + canonical/ → /tmp 副本 → 在副本跑 render → 与仓内逐字节比对
# 差异即红（= 四块与源不同步）；副本渲染同时天然满足「产物只写 /tmp」既有隔离
```
——「副本 render 后与仓内逐字节相同」= 四块与源同步；双守卫（D6）保证 render 不空转、不部分改写。

## 5 影响面

- **消费面**：内容无变化（生成内容与现行逐字相同）；围栏是 HTML 注释，渲染不可见。**常驻 token 微增**：第 1/2/3 块 ×（开围栏 + 说明行 + 闭围栏）= **每模板 9 行**（R18 修正：旧稿「6 行」算式不闭合）；help/README 各 +3 行（不入常驻面预算闸）。余量充足（app 15833/18000）
- **维护者面**：改同文块 → 改 `canonical/` 一处 + 跑 render（原：改 N 处 + 祈祷同步）
- **断言面**：新增 1 条（render 幂等 + 计数守卫）→ 试点后删 2 条旧 byte 互锁，**净 −1**（R5 修正：旧稿「净减 3」把三个**块**误记为三条**断言**）
- **风险面**：见 §8
