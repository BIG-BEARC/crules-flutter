## 4 社区对标（事实均经上游仓库复核，2026-09-08 快照）

| 库 | 形态 | 对比结论 |
|---|---|---|
| [flutter/agent-plugins](https://github.com/flutter/agent-plugins)（**官方**，2.9k⭐） | Flutter 团队维护；skills ×23（Flutter 10 + Dart 13）+ MCP 配置；[官方文档](https://docs.flutter.dev/ai/get-started)直接教安装 | 最大参照系。覆盖通用工作流（测试三件套/布局修复/序列化/路由/l10n/http），但无 memory 体系、hooks 安全闸、双模板、验收判据、CI 守护——工程化层无对标 |
| [evanca/flutter-ai-rules](https://github.com/evanca/flutter-ai-rules)（~627⭐） | 跨工具（Claude/Codex/Cursor/Copilot…）skills ×37 + legacy rules；「No opinions, just documentation」 | token 经济性理念同向但深度浅。**其溯源机制（§5 A1）是最值得整机制吸收者**。Firebase 14 卡与本团队栈无关 |
| [VoltAgent flutter-expert](https://github.com/VoltAgent/awesome-claude-code-subagents/blob/main/categories/02-language-specialists/flutter-expert.md) | 单 subagent 定义 | 主题清单级；其清单点出我们全库盲点：state restoration、golden test、RepaintBoundary、bundle size、深链 |

**格局判断**【判断】：官方库已入场通用层，通用层竞争无胜算亦无必要；本库差异化在①事故沉淀的垂直层（POS/IoT/资损）②工程化层（hooks/memory/守护/审计）③真实工程反馈回路（5w 日活一线反哺）。开源（若做）= core 对齐官方 + 垂直层做差异 + 工程化实践单独输出。
