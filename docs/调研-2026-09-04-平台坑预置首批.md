## 卡 1：permission_handler × Windows 7 启动闪退

- **归属**：插件层（permission_handler Windows 实现）+ Flutter 引擎层（Windows 桌面本身）
- **触发场景**：Windows 7 上启动包含 permission_handler 依赖的 Flutter Windows 桌面应用
- **症状**：应用完全无法启动（issue 原文 "nothing, but app can't start"）
- **根因**：查证到的官方口径——Flutter 本身仅支持 Windows 10+，维护者不为 Win7 投入支持；早期 Windows 10 版本上的同类崩溃源于插件静态链接了新版 Win10 API（PR #1389 改为动态加载修复了「早期 Win10」区间，但不覆盖 Win7）
- **规避**：用 dependency_overrides 指向 no-op 实现（issue #1322 报告者采用 github.com/localsend/permission_handler_windows_noop）；或 fork 插件剔除 Windows 实现；或不将插件引入 Windows 构建
- **区间**：issue 针对 v11.3.1 报告并「Closed as not planned」；其他版本区间——未查证（未见官方 changelog 声明 Win7 支持矩阵，未见修复版本）
- **状态**：部分查到（Win7 不被支持有官方 issue 佐证；精确「哪些版本区间闪退」无官方声明，倾向结论：全区间不受支持）
- **最后核验**：2026-09-04
- **出处**：
  - https://github.com/Baseflow/flutter-permission-handler/issues/1322 （Win7 无法启动，v11.3.1，Closed as not planned）
  - https://github.com/Baseflow/flutter-permission-handler/issues/1388 （旧版 Windows 上崩溃）
  - https://github.com/Baseflow/flutter-permission-handler/pull/1389 （早期 Win10 版本崩溃修复：动态加载 API）
  - https://github.com/flutter/flutter/issues/129716 （Flutter 本体在 Win7 崩溃）
  - https://pub.dev/packages/permission_handler

## 卡 2：iOS 26.x tabbar / draw 渲染异常

- **归属**：Flutter 引擎 / 框架层（iOS 26 Liquid Glass 新 UI 与 Flutter 渲染不匹配）
- **触发场景**：iOS 26 真机/模拟器上运行 Flutter 应用，涉及 CupertinoTabBar / 绘制类渲染
- **症状**：tab bar 样式与 iOS 26 Liquid Glass 不符（内容不延伸到底栏下方）、真机黑屏不渲染、debug 模式不可用等
- **根因**：iOS 26 引入 Liquid Glass 新 UI 范式；Flutter 未实现对应视觉/过渡特性（官方文档列出 iPad 风格 tab bar #150590、liquid glass 支持 #170310 等为「尚未完全实现」）；#186572 黑屏关联 Flutter 3.38 的 UISceneDelegate 迁移
- **规避**：等待官方实现（跟踪 #170310 / #150590）；社区方案 cupertino_native_better 提供 SwiftUI 原生 Liquid Glass tab bar
- **区间**：受影响 Flutter 版本区间 / 修复落在哪个版本——未查证（官方 iOS 26 文档页截至 3.47.2 快照仍未列 affected/fixed 版本；社区信息称 debug 模式问题自 3.35.x 改善、黑屏与 3.38 迁移相关，但无 issue 内里程碑确认，不预置）
- **状态**：部分查到（issue 编号与现象已核实；版本区间未获官方数字）
- **最后核验**：2026-09-04
- **出处**：
  - https://docs.flutter.dev/platform-integration/ios/ios-latest （官方 iOS 26 支持状态与已知问题清单）
  - https://github.com/flutter/flutter/issues/150590 （iPad 风格 tab bar）
  - https://github.com/flutter/flutter/issues/170310 （liquid glass 支持）
  - https://github.com/flutter/flutter/issues/186572 （iOS 26 真机黑屏）
  - https://pub.dev/packages/cupertino_native_better （社区规避方案）
  - https://stackoverflow.com/questions/79747677/ （iOS 26 tab bar 内容延伸问题）

## 卡 3：Android 版本兼容基线（一卡多区间合并）

- **归属**：Android 平台 / 系统策略层
- **触发场景 / 区间**（三子项，官方文档口径）：
  1. **Scoped storage**：targetSdkVersion 29+（Android 10）起分区存储生效；targetApi 29 可用 `requestLegacyExternalStorage` 临时豁免，Android 11 起强制
  2. **Photo picker**：官方页面口径——系统级照片选择器随 Android 11（API 30）+ 原生提供，backport 到 Android 4.4（兼容库，经 Google Play services / ActivityResult）；此前草稿写的 API 33 与官方文档不符，已修正
  3. **Predictive back（返回手势）**：Android 13（API 33）引入预测性返回手势；targetSdk 34+ 对部分组件行为有强制要求（强制细节本次未逐字核验）
- **症状**：越过基线后旧存储 API 失效 / 权限模型变化 / 返回手势行为差异
- **根因**：平台隐私与交互策略演进（官方文档明示）
- **规避**：按官方三篇文档采用 MediaStore / photo picker / OnBackPressedDispatcher + predictive back 声明
- **状态**：大部分查到（API 29 / 33 两个关键锚点为官方文档口径）；photo picker 与 predictive back 的精确回溯/强制版本细节未逐字核验
- **最后核验**：2026-09-04
- **出处**：
  - https://developer.android.com/about/versions/11/privacy/storage （Android 11 存储隐私/scoped storage 强制）
  - https://developer.android.com/training/data-storage （存储总览）
  - https://developer.android.com/training/data-storage/shared/photopicker （photo picker）
  - https://developer.android.com/guide/navigation/predictive-back-gesture （预测性返回手势）
