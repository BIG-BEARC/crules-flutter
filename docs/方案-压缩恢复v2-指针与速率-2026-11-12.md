## 1.5 根本问题与三层解法（v3 落档）

**根本问题精确定义**（非「压缩有害」——压缩只是症状放大器）：

- **自激回路**：压缩丢工作记忆 → 模型重读大文件回填 → 窗口复满 → 比无回路时更频的压缩。实证：b5ae44d8 平均 ~15min/发（17 发/3h52m；发间区间 3–33min、中位 12.6min，平稳持续而非逐发加速——二轮复算）；建库批 22KB 文件重读 ×12（**档案引文**：旧方案 d3124c0 版 §3，as-of 2026-11-09；原始取数 /tmp/pp-direct-test-1109/ 已按 tmp 生命周期视作可能清失——按档案级证据采信，非本机可复算；主控已 git show 原文抽验，见评审档二轮节注记）。**拼接注（二轮 #4）**：节奏实证（b5ae44d8）与重读实证（建库批档案）系两会话，中段箭头为拼接推断——回填占比待试点判据②直接测。
- **窗口胃口**：任务形状层——4h 研磨一窗到底、整文件摄入、状态只活窗口内。runaway 会话＝跳过 brief/分解的形态（b5ae44d8 为 fix 长循环，非 briefed 段）。

**三层解法（乘法关系，缺一不可）**：

| 层 | 承载 | 对根本问题的作用 |
|---|---|---|
| 机制层（本方案 D1-D7） | 指针＋span 直取＋主/子分桶 | **断回路**：每次压缩的回填量从「整文件」降到「几段」——**方向性假设（二轮 #4 降格）**：压缩周期随之拉长，幅度以试点判据②（重读计数）与判据①（频次）对照判读；15min 节奏系回填重读＋工作输出两分量合成，机制层只作用于回填分量 |
| 纪律层（Q9） | ①span 摄入纪律（读先 grep/jq、大件交读客子代理、工具输出限幅）②**窗口是缓存不是记忆**（状态住台账/progress.md，窗口只装当前步）③**分解触发**（预估读 N 大文件/M 步以上先拆段、段间文件交接） | **降胃口**：使 4h 一窗研磨不再必要 |
| 观测层（§4.3 翻账＋§6.2 判据） | compact-report 频次/主子比/runaway 清单 | **闭环**：任务形状的压缩代价复盘可见 → 回流分解决策 |

**诚实边界**：机制层不改变「任务大于窗口」本身——纪律层使大会话不必要、机制层使残余会话不放大，两者相乘；任何一层单独都不够。**Q9 不裁/不落地的后果（二轮 #12）**：只剩机制层——回路只断回填分量，判据①（频次）回落预期相应下调；v3 观察项即既定后手。

**v3 观察项（不入本批）**：UserPromptSubmit 里程碑注入（模型面台账落盘提醒、非用户面打扰）——触发条件数值化（二轮 #9）：试点期频次较混合口径基线回落 <50% 即再议立项（挂判据①收口读数处）。

## 4 设计细节

### 4.1 指针注入件（改造 compact-gate.py，SessionStart(compact)）

注入文案（换血，零指令性催办）：

```
[compact-recovery] 第 N 次压缩（trigger: auto|manual|unknown）。原文未损：
<transcript_path>。恢复纪律：需要细节时 grep/jq 该文件直取相关 span，
勿整文件回读、勿凭摘要臆断已读过的内容。
```

- **计数仲裁（一轮 #1＋二轮 #1·L1 修正）**：正常路径序号与 trigger 均由 ledger 推导——SessionStart 先读账，**去重谓词不依赖 trigger 值**（degrade-A 档 PreCompact 记的恰是 trigger=unknown，若谓词要求 ∈{auto,manual} 则该档每发双记、2 发真实压缩即误触 runaway）：末行 compact 事件 ts 落近邻窗（≤120s）内＝已计（无论 trigger 实值；schema 2 的 hook 字段区分写入者），跳过记账只做注入；否则按 unknown 兜底记账。**谓词升级（首实弹对，§6.1）：同 sid 且同 prompt_id＝同发事件**——实弹三行（PreCompact×2＋SessionStart）共享 prompt_id，两事件输入均携此键；prompt_id 相等即去重（不受压缩耗时长短影响），ts 近邻窗降为 prompt_id 缺失/不等时的 fallback。fallback 窗维持 120s 不放宽：实弹对间隔 96s（余量 24s），而 b5ae44d8 最短发间隔 2m55s（175s>120s）——放宽窗会在 degrade-A 快连对上把两发真压缩误并成一发（漏计比误计危险：失控面失检）。fixtures 挂两用例：同 prompt_id 远隔（>300s）去重、异 prompt_id 近隔（175s）双计。「双记变异测试」列入 §6.2 fixtures，**含 degrade-A 组合**（PreCompact=unknown＋SessionStart 近邻——防谓词回归）。
- 路径解析次序：输入 transcript_path 字段（探针 2）→ cwd+sid 推导＋存在性核验＋mtime 近邻弱校验 → 都无则给 projects 目录通用指引（三级降级）。
- 第 1 发与第 N 发文案同形（仅序号不同）——不再有阶梯语义。

- **任务大于窗口**：指针纪律缓解重读（建库批 ×12·档案引文见 §1.5 的直接对症），但不替代任务分解——17 发/4h 类任务根治归 playbook（Q9 同步条目）。
