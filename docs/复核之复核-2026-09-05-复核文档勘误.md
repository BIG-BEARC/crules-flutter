## 4 补遗（两份前置文档均未记录）

**新1（A1 补强）**：3.47.2 下那条 undefined_lint 的**行号归属异常**——报警文本是 `cancelled_token_use`，位置却指向 [analysis_options.yaml:28](../analysis_options.yaml#L28)（map 条目行）而非其所在第 25 行。说明 `- public_member_api_docs: false` 这个 map 条目至今仍干扰列表解析（只是不再吞掉校验本身）。**删该行的理由比两份文档写的更充分**：既删死配置，也消解析扰动、让报警行号回归正位。

**新2（B1 补强）**：auto-compaction 的 skill 预算除「每 skill 前 5,000 tokens」外还有** 25,000 tokens 合并总池，按最近使用优先填充，更旧的 skill 会被整体移出常驻**（复核只引了前半句）。对 B1 三档的含义：独立成 skill 的坑库（触发时点多晚于写码 skill）在长会话压缩后会被整体移出——仍可靠 description 重新触发，但「引依赖前自动想起」的确定性下降。为「**默认取中档②（skill 内 references/ 拆分）**」再添一条依据，非一票否决③。

**新3（C2 补强）**：edge-to-edge 坑卡还带出 Flutter 侧自有破坏性变更——官方 breaking-changes「default `SystemUiMode` to edge-to-edge」，**用旧 opt-out 机制的 Flutter 应用在 Android 16+ 上可能崩溃**。写卡时「规避」字段应含此条（比纯 Android 侧 insets 适配更贴近本包受众，且属「官方明示」满足入预置门槛②）。

## 5 A3 修法改写（替换复核 §4-A3 方案文本）

读侧 Stop hook 提醒**采纳前必须包含自守卫**（勘A 的直接后果）：

```text
1. 入参 stop_hook_active == true → 直接 exit 0 不再提醒（防连环续轮——官方：连续 8 次即强制结束）
2. 或落盘「本会话已提醒」标记（additionalContext 值存 transcript、resume 回放不重跑 hook——标记按会话粒度）
3. 呈现通道二选一（都走同一套防死循环，自守卫不可省）：
   - hookSpecificOutput.additionalContext（需 ≥2.1.163）：标 Stop hook feedback、无 error 通知——体验好
   - decision:"block" + reason：标 hook error——醒目，但语义偏「阻止」
4. 文案写事实陈述（「队列含 N 条漂移待补索引」）不写祈使句系统指令——官方提示后者可能触发注入防御
5. 硬约束：hook 输出字符串 10,000 字符上限
```

**两机制对比**（A2 方案 B 的取舍应并入同一视野）：

| 方案 | 浮出时机 | 额外模型轮 | 能否浮出队列动态状态 |
|---|---|---|---|
| Stop hook（additionalContext / block） | **每次收尾强制** | 有（自守卫后 ≈ 每会话至多 1 轮） | ✅ 能（读 .pending-updates 实时内容） |
| `.claude/rules` + `paths` | Claude **读到**匹配文件时 | 零 | ❌ 只能注入静态纪律文本（如触发即更新表），看不到队列状态 |

——若「收尾必看队列」是硬需求，只有 Stop hook 做得到；若「涉域时提示维护义务」够用，rules+paths 更便宜且无轮次成本。两者亦可并用（rules 管纪律注入、Stop 管队列浮出）。

## 6 retrofit 预设行裁决选项（唯一落点 [app/CLAUDE.md:180](../app/CLAUDE.md#L180)）

复核勘4 已定方向「保留 + 注明适用面」；本节给三档具体措辞供裁决（预设是引导不是命令，主次排序思路）：

| 选项 | 措辞 | 理由 |
|---|---|---|
| R1（维持原样） | `dio` + `retrofit`（接口声明式）+ `interceptors`（鉴权/日志/重试） | 零改动；但把 codegen 层写成默认装配，小项目过度 |
| **R2（推荐·主次排序）** | `dio` + `interceptors`（鉴权/日志/重试）；**接口规模大可加 `retrofit`（声明式 codegen 层，与 Dio 非互斥）** | 复核「保留+注明适用面」的具体化：裸 Dio 为默认，retrofit 作为显式升级路径；「与 Dio 非互斥」消解「二选一」误读 |
| R3（最简） | `dio`（+ `interceptors`） | 最轻；但丢掉「大规模接口有声明式选项」的提示，预设信息价值下降 |
