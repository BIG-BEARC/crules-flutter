# 方案骨架与配图约定（写设计方案时用）

> 触发场景：写设计方案 / 出方案 / PRD / 实施计划时 Read 本文件。来源：flutter-rules skill「方案骨架」+「配图约定」节（B1 瘦身拆出，内容未改）。

## 方案骨架（写设计方案时用）

**单一模板 + 裁剪档位**。写方案时复制以下骨架按需裁剪：

```text
# <方案名>
> 状态（讨论稿→已确认→已落地/已废弃·指向取代者）· 日期 · 关联需求 · 面向对象

1 目标与范围        要解决什么 / 不做什么 / 老行为变更清单        [需求 Gate ①②③④]
2 核心决策          编号，每条一句话可独立成立                    [方案浓缩·前置]
3 现状              timeline / sequence / 问题表 · 现状对照五档                  [新功能可整节省略]
3.5 行业基线与确定性分级  对标表 + 逐条结论分级            [沉淀类方案必填对标；查项目 memory/reference-map.md]
4 目标方案          候选对比（含平台矩阵可行性列）→ flowchart / 组件职责表 / 规则表 / ER / 接口定义 ＋改动面清单（scope block）
5 影响面            用户 / 数据 / 已有功能 + 平台矩阵影响行 ＋处置态四格（影响面补面细则见下） [方案 Gate ⑤]
6 测试与验收
  6.1 验收标准表    WHAT——业务级判据                              [需求 Gate ⑤]
  6.2 自测用例表    HOW——前置/步骤/预期/平台(矩阵)/结果证据        [涉平台/资损强制]
7 分阶段落地        大需求保留（每批四必答）                        [裁剪点]
8 风险与回退                                                      [方案 Gate ⑦]
9 待确认事项        分组（产品 / 后端 / 设计 / 其他）· 问题 / 责任 / 是否阻塞 · 回填四态 · 快照纪律                         [需求 Gate ⑥]
```

- **裁剪档位**：极简改动 = 1 / 2 / 6.1 / 8 四节；标准 = 全 9 节；大需求（新页面 / 跨模块 / 多端）= 全节 + 独立评审（`plan-reviewer`，见宪法 §三）。本档位是**文档轴**，与收尾三档（任务轴，宪法 §三）各自判定、不互推——极简改动常伴极简收尾、大需求常伴重型倾向，但各随其轴的规模走
- **盲区三扫**（§1 范围）：异常态 / 历史数据存量 / 平台版本兼容性三面各一句「涉 / 不涉＋依据」，不涉也要写明（外源吸收·对方生产实战 2 月·无本仓实证锚）
- **现状对照五档**（§3）：已实现✅file:line / 仅配置 / 需改造 / 需新增 / 无法确认——末档必须直通 §9 待确认并标 ❓，禁裸写「暂不确定」
- **影响面补面**（§5）：涉公共组件/共享层改动时必列复用方回归面（谁在复用＋回归点清单——外部实证：3/5 缺陷出在未触碰页面）；涉依赖/构建脚本/CI 时必列测试构建发布影响
- **改动面清单（§4 · scope block）**：改动落点以封闭 fenced block 列明（`<!-- scope:begin crules-scope-v1 -->` … `path :: action :: note`；action ∈ M/A/D/空；glob 许可、生成连带件〔render-blocks 登记表目标〕须入清单）——收尾机械比对 `scripts/scope-audit.py` 以此为锚（清单外改存量＝越界嫌疑 rc 1；无 block 方案报「scope 缺失·散文判」回落 §1 老行为变更清单）
- **影响面处置态**（§5）：影响面逐行必答处置态，封闭四态＝无影响论证 / 兼容 / 迁移 / 待证疑问单——禁「基本无影响」模糊态；反查为空写「未反查」不写「无影响」（空缺显式化）
- **兼容性条件节**（§1 盲区三扫之兼容面涉及时展开）：四面各答「涉/不涉＋依据＋处置」——存量数据（迁移 / 双读 / 弃旧三选一＋降级路径）／协议（旧版本端共存窗口）／版本共存（灰度期新旧并存）／依赖（新增 / 升级包）
- **视觉规格清单**（UI 类任务条件节）：设计图 → 布局结构 / 间距 / 字号 / 色值 / 组件复用 / 交互态（含空态·加载态·错误态）逐项列出——**图必须被读成清单才算用过**；验收态 FULL/PARTIAL/NONE 由独立 reviewer 标注＋需求方终确认（实现者可自查，不作验收来源）
- **批次卡四必答**（§7 每批）：独立验收判据／依赖方向（数据层→消耗流→UI 先例）／机械验证面（枚举：analyze/测试/脚本/截图；无＝显式 NONE＋汇总上报）／baseline 口径（diff 比对基线：工作区 or 起点 rev——防已 commit 形态假阴性）
- **待确认闭环**（§9）：回填四态＝已解决 / 部分解决附余量 / 未解决附影响 / 冲突（附余量/附影响系本仓增饰注，语义兼容）；快照纪律＝澄清是增量、已确认基线不被覆盖；范围变更触发方案 v2 新档，不回改旧结论
- **6.2 自测用例表生命周期**：方案期写（test-first 前移，写不出用例 = 验收标准不合格）→ 交付期执行（结果列挂证据分级，矩阵列全绿 = 完成定义达标）→ 回归期复用（修 bug / 升级后重跑，成为常驻回归资产）；可自动化项优先固化真测试代码，表内记指针
- **试点/优化类验收用机制性指标**：浪费类零复发、质量闸全绿优先于耗时数字——单次试点（n=1）耗时无法区分「优化生效」与「任务本身小」，方案须声明并以机制性指标为裁决轴，耗时仅参考
- **行业参考查证纪律**：参考条目必须查证带链接出处；查不到标「未查证·凭记忆」——防 AI 凭训练记忆编造同行行为
- **行业基线**（沉淀类方案——把某领域经验提为分发规则的方案——必填）：对标表（维度 / 行业通用做法 / 本项目对照），防止规则滑向项目特有；对标差距即方案立论依据
- **确定性分级**：§2 核心决策及关键事实逐条标 ✅ 亲验（file:line 或 hash 齐）/ ⚠️ 转述或否定性结论 / ❓ 推断待裁——❓ 必须列入 §9 待确认事项并给裁决选项，不得默认成立

## 配图约定（人读文档配什么图）

| 内容形态 | 图型 |
|---|---|
| 流程 / 决策 | flowchart |
| 调用链 / 交互时序 | sequenceDiagram |
| 数据模型 | erDiagram |
| 状态流转 | stateDiagram |
| 演进编年 | timeline |
| 规则 / 枚举 / 对比 | 表格 |
| 命名 / 协议 / 正则 | 代码块 |

边界：**AI 常驻上下文文件不加图**（根 CLAUDE.md / `.claude/memory/*`——图对 AI 无增益、白耗每会话 token）。存量文档补图用 `/crules-flutter:diagram`。
