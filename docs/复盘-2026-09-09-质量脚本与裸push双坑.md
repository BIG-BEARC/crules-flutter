# 复盘 · 质量脚本裸跑与裸 push 双坑（checklist 实证搬家）· 2026-09-09

> 本篇是 checklist 条 6 / 条 8 实证叙事的**搬家落位**（2026-09-09 精简批）：规则本体留在 checklist 一句，完整故事归此——指针有目标，压缩不悬空。

## 坑一：裸跑默认参数的质量脚本 → 一次波及 166 文件

**现象**：消费工程直接裸跑 `dart format`，默认行宽 80 × 工程门禁 120 宽——一次提交波及 166 个文件，review 不可读、回滚困难。

**修法（规则化）**：工程自定义质量脚本（format / analyze / check）**即唯一入口**——CLAUDE.md / §十二 写明并禁裸跑默认参数命令。

**排障提示**：此类「脚本行为与预期不符」先验插件 hook 加载路径（`hooks/hooks.json` 是否存在）——声明文件存在 ≠ 已加载行为。

## 坑二：cwd 命令间重置 → 裸 push 把主仓推出新远端分支

**现象**：Bash 工具每次调用的 cwd 会重置回主仓；依赖「上一条命令 cd 过去了」的假设，命令间裸 `git push` 把主仓推到了非预期远端分支（实战第 7 踩）。

**修法（规则化）**：多仓 / 子模块 git 一律 `git -C <绝对路径>`（`cd && git` 依赖 cd 落位，命令间 cwd 重置时连上一条验证过的 pwd 都不可信）；push 等外发操作前，命令内先 `git remote -v` 核对目标仓再推；跨仓收尾必跑 `git status` 验零污染。

> 同族坑（cwd 重置误写母版）见 `复盘-2026-08-27-批2c双坑.md`——本篇是其外延：**写**与**推**两个方向都被 cwd 假设坑过。

## 坑三：entity 有字段 ≠ 接口会返回（订单折算复盘残篇搬家）

**现象**：复刻在线版订单页时，entity 里有 `payName`/`paymentName` 字段，模型按字段名猜接口返回——全空。实际名称是消费端按 `payType` **前端补写**的，服务端根本不返回。

**修法（规则化）**：复刻在线版接口消费时追到 logic / 消费端确认字段来源；entity 头部**样例响应注释优先看**，可省一轮返工。
