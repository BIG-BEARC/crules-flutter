## 0. 缘起与定位

本系统给一切建了测量（token 预算闸 / 观测带数 / 外审台账 / 生成闸），唯独没给**自己**建——「宪法到底被遵守了几成」此前只有 AI 自我汇报一种数据源，恰是本仓定义为不可信的那类证据（1.0.26 诚实边界自认）。本文 = 普查表（每条规则配执法点）+ 批1 探针脚本的实测记录。

**三原则**（探针设计的承重柱，批2 继承）：
1. **记事实，不出结论**——多会话共享工作树、跨会话批次、语义授权等现实使「违反」判定极易误伤；定罪归 distill 聚合与人（对齐 §五 ledger→§7→人裁决分工）。
2. **转录只作采料场**——本机实测留存仅数日（2026-09-22 查：本仓目录最旧 09-20、共 21 份）；持久账批2 起落盘 `.claude/memory/.compliance-log`。
3. **窗口口径钉死**——数据只覆盖 2026-09-20 之后（启动后窗口），**不是全历史**；33 次既往 review 无法回填。防「窗口内数据」被读成「历史总账」（与「无数≠零样本」同族病）。

## 1. 普查表（双模板协作层 §一–§六）

**类标含义**：闸 = 机械构造保证（hook/lint/宿主）· 强签名 = 收尾对账可定罪 · 弱签名 = 只记不判 · 语义 = 只能 AI 抽样审。
**头一个发现**：转录在手后「完全无痕盲区」几乎消失——遵守度变成四档覆盖声明（闸集合 + 对账集合 + 弱签名集合 + 语义集合），各档数量本身即可随版本追踪。弱模型场景的显式契约：散文层失效时剩余保障 = **闸集合**（现在是可列举的表，不是一句自认）。

| 规则 | 类标 | 签名 / 落点 |
|---|---|---|
| 风险操作确认（强推/硬重置/rm -rf 族） | 闸·已有 | deny-list py+ps1 |

## 2. 检查集六项与两栏切分（批1 脚本实现）

**宣约档**（检查模型自己的输出物形状——零打扰、当场可改、误报面小）：①汇报三件套标记 ⑤commit message 格式 ⑥派单切片包令牌（派单 prompt 是主控自己的输出物，归宣约）。
**世界侧**（记事件配对事实，永不定罪）：②Gate/ledger 台账行数 ③commit×触发词 ④声明×执行比值 + deny/ask 命中计数（转录白拿，反馈环样本）+ **解析率**（防「解析静默归零被读成全遵守」——「无数≠零样本」病的 hook 版）。

## 3. 批1 实跑记录（2026-09-22，只聚合、不外显消费仓对话内容）

首跑事实（解读归人，以下只是标注）：
- **派单契约**：09-20（1.0.27 随装）后消费仓评审派单 **14/14 无令牌**、本仓 3/4 无令牌——「主控派单不带包」是当前实况，1.0.27 传感器首个读数即高命中。⚠ 读法坑⓪：令牌依赖消费仓装到 **1.0.27+ 的宪法层**（**批2 实机已核：saas-cashier 版本戳 = 1.0.25**——故该仓 13/13 无包属**预期缺位、非无视条款**，坑⓪由假说转实证；且派单自检（主控侧）与卡内自护（代理侧）是两个执法点——本检查只测前者；退回与否须看子代理自己的输出（isSidechain 行，批3 可扩）。定性「无视条款」前先核版本送达态。
- **三件套**：实施类会话 18/18 末条缺标记。⚠ 读法坑①：**进行后会话的末条本就不该有三件套**（收尾未发生），缺 ≠ 违反——需配收尾态甄别（候选信号：末条含 commit 授权问句 / 长时间无新事件），批2 裁决此项启发式或按「仅记」处理。
- **deny/ask 命中**：本仓 57 次中含**自测夹具触发**（test-self 跑 deny 用例即产生拦截文本回传）——读法坑②：需剔自测会话（cwd 为本仓且转录含 test-self 执行特征）。消费仓 4 次为真实拦截候选，反馈环「野外样本」首次可寻。
- **声明×执行**：本仓 62/71、消费仓 61/82，量级相当（比值健康只作趋势）。
- **commit×触发词**：消费仓 1 会话 commit 而全窗口无触发词（读法坑③：授权可能发生在留存窗口外的早前会话——回填不可得，窗口口径的又一体现）。
