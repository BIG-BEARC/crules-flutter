# 审查与复核纪律

> **fork 声明**：本篇 fork 自 crules `v74-fork-base`，由 crules-flutter 独立演进。

> **启用条件**：项目需要 code review、资损评估、安全审计等「给出结论」的任务时按本篇纪律走。
> 配套根规则：宪法（`.claude/CLAUDE.md` 指针 → `.claude/crules/constitution.md` 副本，1.1.5 丁-Copy）。本篇不重复根规则（提交、范围、不虚构等），只补充审查的专门纪律。
> 启用 superpowers 时，两阶段审查叠在 `requesting-code-review` 上，skill 映射见宪法 §九（superpowers + dart-flutter 协作）。
> **审代码（实施后）**：本篇审**代码**。实施**前**的**方案**审见 [`方案评审闭环.md`](方案评审闭环.md)。

## 核心区分

**【代码层面成立】≠【业务真实可达】。** 先验证业务场景，再定级。不得把「代码路径上能走通」直接当成「线上必现」。

---

## 业务可达性 Gate（上报前必过）

每一条审查发现，上报前**必须**回答：「它在真实业务流程中如何触发？」按可达性分级标注，禁止把低等级当高等级上报。

**定级前先查约束**（若启用记忆库）：`memory/business-rules.md`（业务规则——触发条件被否定 → 降级 / 撤条）+ `memory/INVARIANTS.md`（技术不变量——发现疑似破坏不变量 → 单列上报，不并入可达性定级）。

| 等级 | 含义 | 默认定级上限 |
|---|---|---|
| **L0 代码路径成立** | 仅静态推断能走通，未证实触发条件 | Low / 信息 |
| **L1 触发条件存在** | 有触发路径，但业务上是否存在该组合未证实 | Low–Medium，注明「待证」 |
| **L2 业务真实可达** | 已证实真实业务流程可触达，且无前置拦截 | 按实际影响定（**须需求方确认**） |

> **AI 能力上限是 L1**（触发条件存在）；L2（业务真实可达）是业务事实判断，不在 AI 能力范围，**必须需求方确认**。规则是「要求」不是「能力」——写「必须追到生效路径」≠ AI 真能追到代码之外的业务。未在 `business-rules.md` 沉淀的新业务，用疑问单上报（见下）。

- 「字段 / 变量用错」类发现，**必须**追到【它在生效路径上是否真的非空 / 被读取】，不得停在赋值处就定级。
- **必须**检查 UI 层是否已禁用该入口（`isGray` / `disabled` / 条件拦截），被拦截的路径不得按可达上报。

### 疑问单（新业务 / 未沉淀的可达性）

查 `business-rules.md` 未命中、AI 又无法自证可达性的发现，**不直接定级上报**，改用疑问单交需求方：

| # | 发现 | AI 的可达性判断 | 问需求方 |
|---|------|---------------|---------|
| 1 | <代码现象> | <L0/L1 + 为何到不了 L2> | 「此业务场景实际是否存在？入口是否触发？」 |

需求方判定后：不可达 → 撤条 + 沉淀 `business-rules.md`；可达 → 按实际影响定级。

## 子代理与工具结论复核

- 子代理、搜索工具、静态分析返回的发现是【**待验证的线索**】，不是结论。
- 主控上报前**必须**亲自读关键代码确认触发条件，不得整段搬运子代理的推测性表述。
- 复核范围：触发条件、前置拦截、字段在生效路径的读取情况、业务组合是否真实存在。

---

## 资损 / 金额类评级克制

- 资损、金额、库存等高敏感发现，评级尤其克制。
- 稳态流程走不到的路径，降到 Low / 边缘，并明确写出【为何测不出】的机制。
- **禁止**仅凭「代码能走通」或「字段值可疑」就定 Critical。

---

## 领域专家否决

- 需求方是该系统领域专家，业务可达性以其判断为准。
- 其明确指出某业务场景不存在、某入口不会触发时，直接撤掉该条发现，**不反复辩护**。
- 撤条时保留一句「经确认业务不可达」，供后续追溯；**同时沉淀一条进 `memory/business-rules.md`**（若启用）——把这次否决变成永久规则，下次同类问题自动消音。

## 两阶段审查（编排）

审查任务**分两轮独立输出**，不混在一起：

**共同前置 — 测试先读**：开审先读该变更自带测试——存在性、测行为而非实现细节、边界覆盖、命名达意、回归真发生时测不测得出；测试先暴露意图与覆盖面，再走代码。末问以实验作答：**变异抽查**——反转变更引入的一个条件（去否定、`&&` 换 `||`）跑套件后原位还原，仍绿 = 测试缺陷，点名缺失用例；执行归机械验证 / 自测档（reviewer 无执行工具，只静态判可疑并在报告点名待抽条目）。

**第一阶段 — 规范合规（Spec Review）**：只看是否覆盖 PRD / 任务清单功能点；Loading / Empty / Error / 鉴权失效 / 超时等边界；i18n 是否多语言补齐；是否守住踩坑记录。**不评论**命名风格、不要求重构。

**第二阶段 — 代码质量（Code Quality Review）**：只看颜色 / 文本样式 / 间距是否归口；暗黑 / 主题 / 适配是否走统一扩展；状态管理用法与生命周期；DRY、命名、单组件行数；是否绕过现有抽象重复造轮子。**不再回头**讨论功能完整性。

所有 🔴（必须修）项修复后才算通过。

结构性主张（重构 / 拆分 / 换抽象）按**推定性阻塞**处理：先以建议级提出并给更简设计，证实实际恶化（复杂度搬家、大文件继续膨胀、特性逻辑进共享物）才升 🔴——不以「我会那样写」把风格偏好升格为阻塞项。

## review 主工位与范围

**时机（嵌交付流水线，非独立仪式）**：

```text
方案 Gate ──► 实施 ──► 机械验证 ──► ★review ──► 自测执行 ──► 交付汇报 ──► 授权提交
(plan-reviewer)          (build/test    (主工位)    (6.2×矩阵)  (必含review    (feat+docs
                          /lint/CI)                              结论+证据)     两笔)
```

- 卡位理由：review 是静态问题的最晚便宜点——先审后测省一轮真机重跑
- **review 修复后的复验 = 重跑受影响构建 / 测试 + 重审修复涉及的部分**（与工程化流程 §5 表述对齐；复验不是第三轮全量审查）
- 分级触发：极简改动 = 主 agent 对照插件 cache `checklist.md` 自查；普通需求 = `reviewer` agent 独立上下文 + 人审关键 diff；涉资损 / 跨模块 = 强制 `reviewer` agent + 人审
- 特殊时机：后台 agent 完成即审（根规则 §六 diff 展示即 review 面）；大需求分阶段节点审
- 交付汇报模板（含 review 结论位 / 沉淀候选位）见 [`工程化流程.md`](工程化流程.md) §7——单一权威

**范围**：diff 为圆心、**引用链为半径**——改共享物（组件 / 函数签名 / 公共配置 / 文案 Key）时引用点全工程级纳入（教训：只分析被改文件，校验不到其他调用方）。

## 校验层（重型收尾专用：review 结果的二次质检）

> 触发：收尾档判**重型**（跨域大改 / 公开 API / 资损面——判定见宪法 §三）；标准 / 极简收尾不启用。

- **做什么**：review 发现派**隔离子代理**独立校验——上下文隔离必须、模型档 **sonnet 起步**（与 reviewer=opus 异档）；**推断级条目逐条强制、已验证（带 file:line）条目抽查**（全量逐条成本收益失衡）；输入 = 条目原文 + diff 引用链，插件 cache `checklist.md` 与相关 memory（业务规则 / 不变量）**只读引用**作静态基线；每条出 **CONFIRMED / REJECTED / 更优方案** 三值之一，附**可复核**证据（REJECTED 尤须——驳回须能被复验）；reviewer 漏报的新发现随结论上报并入分流。**只校验不改码**。
- **分流**（主控按条目类别 × 结论）：低危 CONFIRMED（机械可判 / 规范类）→ 列单默认修；**业务语义类**（涉行为取舍 / 业务规则 / 需求意图——类别存疑一律升此类，fail-closed）或 L1+ → 列单需求方裁决；REJECTED 且原条目 L1+ / 已验证 → 需求方确认后生效（维持驳回 → 误报，翻案 → 采纳）；REJECTED 其余 → 记驳回理由、不修；有更优方案 → 需求方裁决——**校验者主张（非已验证事实）**，与 reviewer「推断级」同等对待。
- **轮次**：单轮为默认；仅**证据对峙型分歧**（结论与主张互斥且各有证据）加轮重校一次，**上限 1 轮**、不重跑全量；仍对峙 → 事实分歧（行为是什么）双方**预注册预言**后表征测试仲裁，应然分歧（该不该）直接需求方。
- **留痕**：分类与结论全部落 `.review-ledger`（五值沿用）；低危默认修复被需求方否决 → 回滚该改动、verdict 落「误报」（校验层放行失准的质量信号）。

## Review Checklist（逐条对照）

> 通用条目，按项目技术栈裁剪。审查时逐条 PASS / FAIL + 原因，FAIL 项附修复建议（精确到文件行号）。
> **规则全集矩阵**：对照面沿两层 CLAUDE.md 链（宪法通用层 + 子工程层）枚举全部强制规则逐条过，**不从「已发现的问题」出发点状补查**——审查锚定已发现的问题，换轴即出新盲区（实证：2026-10 挂账收尾合规审查四轮追问每轮漏新违规，第四轮转全集矩阵才抓尽）。**可机械化条目必附扫描证据**（Grep 模式 + 命中数 + 落点，禁凭印象报 PASS）；判断类条目（架构 / 状态管理 / 功能完整性）维持逐条对照。**行为等价性判定先于重造修复**：同域能力 ≠ 行为等价——提议替换既有实现前逐分支比对行为，不等价只登记差异呈报需求方裁，不直接重造（实证：手机号脱敏两实现分支行为不同，直接替换即照抄错实现）。
> 实证口径：条目中『私有仓生产实证』＝crules-flutter 维护方消费工程实证、外界不可复现——同插件 cache `checklist.md` 头部口径行。

**0前. 验证事实纪律（根模板裁剪补遗）**：接口 / 数据结构以**真实响应**为准（真实抓包或运行日志确认，不从文档印象推测）；**构建 / 测试通过 ≠ 规范合规**——自定义 lint、主题 / 样式归口、控件选型等规范项常不在构建与测试覆盖内，须显式自查；**grep 空结果 ≠ 不存在**——下「查无 / 全库无」类否定结论前先验搜索面非空（子仓工作树检出态，必要时 `git -C <子仓> grep <词> HEAD` 打对象库）——实证：后端子仓整体未检出，工作树 grep 空被当「全库查无」存活一轮（消费工程五轮复盘 E1，2026-10-09）。**grep -v 误杀陷阱**——排除式过滤把混合行（同行一半合规一半违规）一起滤掉出假阴性，禁以 `-v` 构造扫描面；裸值扫描用锚定正则（如 `(^|[^_a-zA-Z.])Color\(0x`）——实证：斑马纹 4 处颜色违规被排除式扫描滤成假阴性存活一轮（2026-10 挂账）。

**0. 协作表达**：沟通简练精准；先给可执行结论；无废话 / 重复 / 过度铺垫。

**1. 架构合规**：遵循分层（表现层 → 逻辑层 → 数据层 → 网络）；表现层只渲染不做业务逻辑；每个视图只调自己的页面级状态 / 聚合层，禁止跨页或跨层直接订阅多个底层源；跨源组合经聚合层暴露；网络 / 存储走统一封装，路径 / Key 集中定义。

**2. 组件 / 视图设计**：拆分粒度合理（单组件约 200 行内）；复用组件归公共目录；间距 / 圆角 / 尺寸用约定值或主题常量；无硬编码颜色。

**3. 状态管理**：状态单元职责单一；生命周期合理（页面级 vs 全局单例）；非平凡实现已先获确认。

**4. 边界处理**：Loading 有反馈；Error 有用户可见提示；Empty 有占位；网络异常有兜底（离线 / 重试）；输入校验走统一工具；长操作（外设通信 / 上传 / 长连接）有超时与断连处理；**吞异常禁令**——`catch (_) {}` / catch 无日志 / unawaited Future / errorBuilder 返回空不记录，处置三态（处理 / 上抛 / 记录后降级）禁止第四态（吞）；**正常路径静默丢弃同罪**——后台消费路径（消息分发 / 转发 / 长连接回调）提前 return、未匹配分支丢弃输入，同按吞处理须留日志（坑库网络域现行实证三处丢弃路径，见 skill references/network-comms.md）；边界场景清单——null / async 时序（取消 / 竞态）/ 生命周期（dispose 后回调）/ 弱网离线 / 超长列表 / 权限拒绝 / 多语言长度 / 平台矩阵各端 / 窄屏极值（分栏布局按最小窗口逻辑宽过一遍）；调试期空值先显式暴露或打日志，**不加兜底文案**——兜底把字段错位 bug 变成「显示为其他」这类更迷惑的现象，延迟定位（字段契约确认后再兜）。

**5. 国际化**：用户可见文本走 i18n；新增 Key 同步多语言文件；必要时执行 i18n 代码生成。

**6. 代码规范**：文件头注释（如项目要求）；无调试日志（**`avoid_print` lint 已拦**，抽查即可）；无硬编码 URL / 密钥；**服务端协议码 / 枚举值禁以字面量落 switch / 比较——必经枚举 fromCode 或常量类归口，发现 1 处必 grep 同类全量清点（单点修复 = 漏报；对齐在线版同款字面量照抄亦不放行）——实证：时间类型码 '1'/'2'/'3' 一类散落 notifier 十余处后收敛常量类，需求方定调「魔法数或硬编码应抽取出去」，高频重犯类（2026-09-21）**；UI 间距 / 尺寸类字面量归条 2 不在此重复；命名规范；**无新引入 lint 警告（`flutter analyze` 零 warning 是硬门——lint 基线走项目自己的 `analysis_options.yaml`；crules-flutter 1.1.5 起仅随 init 给 AO 建议稿 `.claude/memory/analysis-options.suggested.yaml`，人择采纳）**；import 分组有序；资损线（支付 / 订单 / 打印 / 同步）结构化日志带追溯上下文——orderId 可记，**token / 密钥 / 完整卡号永不入日志**；机械项（analyzer / lint 违规）归 CI 基线，不占人审注意力；**闸红修因不绕闸**——diff 中禁测试删除 / 注释 / 跳过、禁断言放宽凑绿、禁超时放大吞 flaky（flaky 修到稳定为准，重跑通过不算清账）；**工程自定义质量脚本（format / analyze / check）即唯一入口**——`.claude/memory/PROJECT.md` §十二 写明并禁裸跑默认参数命令（实证：裸 `dart format` 一次波及 166 文件——私有仓生产实证，口径见头部）。

**7. 功能完整性**：spec 功能点均已实现（非 stub）；用户可完成完整流程；关键路径无崩溃；新增入口 / 路由已注册；老行为变更清单（方案 §1）外的行为变化 = 回归 bug。

**8. Git 规范**：commit message 清晰；**纯重构（无行为变化）与功能 / 修复分笔提交**——混笔难 review、难回滚、难定位肇因；不提交不该入库的生成文件；不提交调试临时代码；iOS 生成文件（Generated.xcconfig / flutter_export_environment.sh）按机器路径假变更，pathspec 排除后再提交；多仓 / 子模块 git 一律 `git -C <绝对路径>`，push 等外发操作前命令内先 `git remote -v` 核对目标仓再推（实证：cwd 命令间重置，裸 push 把主仓推出了新远端分支——私有仓生产实证，口径见头部）。

**9. 资损红线【0.4.0 新增】**：金额计算（精度 / 舍入）、幂等（重复提交 / 重试——**支付/退款/撤销/核销类接口核「请求号+在途锁」与重试白名单，判定线与口径见 flutter-rules skill 支付域**）、状态机非法迁移、并发扣减——涉钱 diff 强制逐项过；**修一处清点同类入口**——涉钱链路改动先检索同类提交 / 撤销入口全落点逐个核在途锁，禁靠记忆清点（实证：会员管理逐入口补防重漏了撤销入口，2026-09-20）；金额展示铁律——主金额固有宽完整显示不可截断（ellipsis 只作用于划线单价等辅助信息）。**存量数据兼容（条件条——涉本地存储结构 / SP Key / 缓存格式变更时查，其余跳过）**：迁移策略已裁决（迁移 / 双读 / 弃旧三选一）、降级路径明示（迁移失败读得出默认态，不白屏不挂死）——实证：SP 文件被旧版本改写致 deviceId 漂移「换号」（skill 坑库 SP 卡，saas-cashier 三笔补丁）。

## 审查汇报格式

发现清单按**杠杆排序**上报：正确性 / 安全 > 结构性回退与漏掉的简化 > 其余——一个结构问题加十个 nit，结构问题才是这次评审。

```md
## 审查范围
- <模块 / PR / 版本>

## 发现清单
| # | 发现 | 可达性等级 | 定级 | 触发机制 / 为何测不出 |
|---|------|-----------|------|----------------------|
| 1 | <描述> | L0/L1/L2 | Low/Med/Critical | <证据或机制> |

## 已撤条
- <发现>:经确认业务不可达(<依据>)

## 复核说明
- 哪些发现已亲自读码确认触发条件;哪些仍为子代理线索待证。
```

## 案例 Why（不入正文，仅溯源）

一个连续称重功能的审查过判：① 重量字段存 total 非 delta 被当 Critical，实际后端不回传、试算回灌清空、删菜恒走 fallback；②「某核销入口绕过称重锚定」——业务上该核销场景根本没有称重菜；③「数量守卫缺失」——按钮已对相关商品禁用（`isGray`）拦截了点击。分别对应 L0→L2 误判、业务组合不存在、UI 拦截未查。沉淀为业务规则见 `memory/business-rules.md`（称重域示例 WR-WEIGH-001～003）。
