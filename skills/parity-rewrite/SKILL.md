# Parity Rewrite：复刻/重写一致性保障

## 触发识别

**触发**（共同特征：**已有一个参照实现，要求行为一致地重建**）：

- 复刻：在线版 → 离线版、老版 → 新版
- 重写：同栈重构、跨栈迁移、技术栈换血
- 模块级对齐：以某实现为基准把另一处改到一致

**不触发**：

- 纯新功能（无参照实现）
- bug 修复（改的是缺陷，不是对齐）
- 纯样式/文案微调（无行为面）

## 第 0 步：加载项目规则（强制，先于一切动作）

1. **定"项目"边界**：多层仓库里，"项目"= **目标模块所在的那条 CLAUDE.md 链**，不是仓库根。先定位目标模块目录
2. **沿链向上溯源**：从目标模块目录逐级向上收集每层 CLAUDE.md，直到仓库根；展开各文件中的 `@` 引用
   - **不读旁支**（其它子模块、无关服务的 CLAUDE.md）
   - **隐式链是主路径**：分层生效靠目录层级，未必被任何文件显式引用——只看 `@` 引用会漏掉整条链
3. **收集守卫 skill 清单**：该项目 `.claude/skills/` 下的全部 skill
4. **取得资产底账**：沿链查找项目**已有**的组件/公共资产索引（适配节给指针）→ 有则读之并核对"最后更新"时间戳（过旧要求按项目刷新流更新）；无索引才按 [references/boundary-asset.md](references/boundary-asset.md) 派生——**派生脚本系项目侧资产，其落位与产出责任在第 6 步共建流程中向需求方确认后才建，skill 不自建**；两者皆不可得则记录"无底账"，Phase 3 核对退回人工翻查并逐项写结论
5. **生成规则映射表**：逐条注明**来自哪一层**、在本流程哪一步、以什么方式介入（否则规则会被当"背景音"忽略）
6. **沿链查找「复刻对齐适配」节**——该节**只补 CLAUDE.md 未覆盖的缺口**（参照源 / **参照实现侧弹出口形制清单**（[references/closure.md](references/closure.md) 双侧闭包用）/ **共享边界定义**（[references/boundary-asset.md](references/boundary-asset.md)「防外溢闸」机械判据的前件：哪些目录/文件形态算共享，适配节给派生指针或清单）/ 清单归档目录 / 风险分级落地 / 视觉验收方式 / 组件资产底账指针 / 并行执行形），已有规则只给指针不重述；多层都有时**越靠近目标模块的层优先**
   - **有** → 加载
   - **无** → 与需求方逐项共建该节，**回写目标模块层 CLAUDE.md**，再继续

**冲突优先级**：项目规则 > 本 skill 方法论 > 模型默认行为。因项目规则导致流程偏离时，登记到清单第 8 节，不静默执行。

**指针必须核实**：适配节里每条"见 XXX"的指针，都要实际打开确认存在。"我记得项目里有这么个文件"不算——未核实的指针会让人误以为规则已生效。

## 铁律

1. **先钉现状，再动手**——不问"应该怎样"，只问"现在怎样"
2. **不改哪里写清楚**——禁夹带优化、禁动接口语义
3. **单源项 = 高危盲区**——只在数据面或只在页面面出现的项，必须重点核对
4. **每项必须落到测试**——完成判定 = 测试绿
5. **quirk 默认照搬**；疑似 bug 显式上报，不替需求方做业务判断
6. **人控边界，AI 扛执行**——目标/边界/风险接受归人；**凡需裁决处，最终决定权在需求方**，默认策略与打包呈报只是降低单案成本，不构成预裁
7. **失败可回滚**——每批次有回滚点与停止条件
8. **项目规则优先**——工程已有规则（CLAUDE.md + 守卫 skill）高于本 skill 方法论；偏离必须显式登记
9. **不虚构事实**——方案、清单、适配节里出现的每个文件路径、节标题、skill 名、数量，都必须核实到真实存在；"我记得有"不算
10. **遍历含弹层**——page 之外的弹窗/面板/抽屉按「页面-弹窗树」强制枚举（**出口闭包规则**见 [references/closure.md](references/closure.md)：原生 API + 封装体调用点迭代并入 + 隐性事件源），完整性以 [references/closure.md](references/closure.md) 出口闭包完整性单一判据为准——「本批作用域内闭包完整、作用域外逐条登记待后续批次」，不许有空格也不许有沉默
11. **双向防越界**——改共享件必经需求方裁决 + 全引用方功能测绿；新建公共形态件必先过资产核对（复用 / 核对过且不适用+原因），不许沉默略过
12. **定稿前不并行**——清单未定稿、主档未定稿的工作不派并行；写面相交的定稿后工作才 fan-out

## 流程

Phase 1 枚举 → Phase 2 清单定稿与定级 → Phase 3 分批重建
→ Phase 4 比对验收 → Phase 5 归档

### Phase 1｜枚举（四步，双向夹逼）

- **Step 1 数据/网络层**：接口、数据模型、字段值域 → 对齐清单
- **Step 2 功能清单**：由接口反查调用点/触发点/前置条件/入参
- **Step 3 UI 功能清单**：遍历对象 = **「页面-弹窗树」**（见 [references/closure.md](references/closure.md)）——page 功能点与全部弹层（按 [references/closure.md](references/closure.md) 出口闭包规则反查：原生弹出口 + 封装体调用点并入 + 隐性事件源），逐节点登记父子链；**同步标记文案点（l10n key，尤其拼装模板）与视觉关键值（换算后）**；每节点登记**复用面**（引用方计数+名单，模块内/外分标，见 [references/boundary-asset.md](references/boundary-asset.md)）
- **Step 4 下游递归**：page 上的功能是否还有下一个功能页面，继续罗列；弹层节点按树深度递归，不因"是弹窗不是页面"而停

清单是活稿；Step 3 可反哺 Step 1。**只在单边出现的项单独成表核对。**

### Phase 2｜清单定稿与定级

- 每项打**来源标**：数据面 / 页面面 / 双源
- 每项打**风险级**：P0（资金/权限/撤销链路）/ P1（其余）
- 每项写**对照断言**：断言值直接从参照实现源码 / 真实响应摘录
- 每项**映射测试用例名**
- **quirk 单列**：照搬项标 `对齐参照实现 quirk`；疑似 bug 单列上报待裁决
- **定稿 = Human Gate**：需求方确认「这张表完整」才开工（见 [references/rework-ledger.md](references/rework-ledger.md)）；**"完整"的判据 = [references/closure.md](references/closure.md) 出口闭包完整性单一判据**（作用域已于 Phase 1 前划定登记 + 本批作用域内闭包完整 + 作用域外逐条登记待后续批次 + 前批「待后续批次」行全部销账核对），定稿包须附闭包核对与销账核对结果；此闸未过不并行、不落码

### Phase 3｜分批重建

按 P0 → P1、按模块/里程碑分批。每批先产出**五要素 Task 文件**（做什么 / 改哪里 / **不改哪里** / 怎么验 / **失败怎么办**），再执行。「不改哪里」必须点名本批涉及的**共享件**（默认不动，动则已走 [references/boundary-asset.md](references/boundary-asset.md) 裁决）。

**执行时按第 0 步的规则映射表调用项目守卫 skill**（**按本模块实际涉及的挑**，不逐个全调），批次收尾走项目唯一的格式化 / 质量门禁入口（路径基准以该层 CLAUDE.md 记载为准）。

**落码前置闸（[references/boundary-asset.md](references/boundary-asset.md)）**：新建控件/工具/弹窗结构前，先过资产核对，结论只许「复用 X」或「核对过 X/Y/Z 不满足+原因」，且引用第 0 步底账的稳定锚（组件名+路径）。**「动了共享」按 [references/boundary-asset.md](references/boundary-asset.md)「防外溢闸」机械判据自判**（diff 触及共享目录/名单文件即命中，含加参数改默认值）。

**编排**（见 [references/orchestration.md](references/orchestration.md)）：定稿后识别写面不相交的可并行项（多语言从档、独立子模块），按适配节记载的并行形 fan-out 子 agent；决策类工作（清单、P0 断言、quirk、接口语义）不并行。

### Phase 4｜比对验收

- 测试矩阵全绿 = 一致性达标；**每批全绿才进下一批**（硬闸，见 [references/rework-ledger.md](references/rework-ledger.md)）
- **项目规则合规**：跑项目守卫 skill 的校验脚本（如内联样式扫描），不通过即未达标
- P0 项终审必过
- **共享件回归**：批次若动过共享件，全部引用方涉及功能测试覆盖且全绿（[references/boundary-asset.md](references/boundary-asset.md)「防外溢闸」），并跑边界守卫 skill（如 shared-boundary-review，适配节给指针）
- **对偶反查重造**：批次新建的公共形态件反查工程是否已有同能力件，有即返工项（[references/boundary-asset.md](references/boundary-asset.md)「防重造闸」）
- UI 批次：目标平台视觉抽查（抽查点 = 清单视觉层项）；纯逻辑批次免
- **返工登记**：验收发现的漏项回填清单 + 根因归因（枚举漏/假设补/弹窗树未进/重造/越界），随批归档（见 [references/rework-ledger.md](references/rework-ledger.md)）

### Phase 5｜归档

- 对照清单归档到项目指定目录（**参照源在清单头部逐条记录**——不依赖任何"导航文件"，除非项目确有该文件且已核实）
- 若项目有导航 / 索引文件且**实际存在**，在此挂"对照源"指针；不存在则跳过，不虚构锚点
- 沉淀候选走项目闸流程（不直写闸类落点）

## 模板

`templates/parity-checklist-template.md`——对照清单模板；模板本身不含具体项目的数值，项目参数由第 0 步从适配节注入；填充后的清单文档归档到项目根内适配节指定的清单归档目录

## 反面清单（这些都不做）

- 不先"彻底看懂"再动手
- 不做大爆炸式全量替换
- 不把清单当一次性文档——它是活稿
- 不把"AI 说一致"当证据
- 不跳过弹层——弹窗/面板/抽屉是树节点，"不是 page"不是免枚举的理由
- 不沉默略过——"没找到"必须写成"翻了哪、为什么不适用"；作用域外节点必须登记「待后续批次」行（算已填、待收账），与"行没填"的空格是两种形态，都不许以"以后再说"代替
- 不动共享件不自知——改前无引用方名单、无需求方裁决，即越界
- 公共空间有件而自写，且给不出资产核对结论——即重造
- 未定稿先并行——定稿是闸，并行只给写面不相交的定稿后工作
- 不替需求方决定 quirk 与 bug
