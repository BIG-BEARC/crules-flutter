# 执行编排：主从并行

> 本文件为 parity-rewrite skill 机制条文，SKILL.md 执行到〔Phase 3 编排〕时 Read 本文件。

**病灶**：可并行的活排队串行做（实战例：多语种文件逐语种手搬）。

**通用原则**（skill 主体只放判据，不放具体并行形）：

- **可并行判据 = 写面不相交**：多项改动不同文件、无相互依赖 → 派子 agent 并行（典型：多语言从档、独立子模块、互不引用两端）
- **主从模式**：先由主串完成「定稿类」工作（主语言文案模板、接口契约、清单定稿），**定稿是闸，没定稿不并行**——否则并行放大返工；定稿后 fan-out 侧翼
- **不可并行清单**（防为并行而并行）：清单定稿、P0 断言设计、quirk 裁决、接口语义确认——这些是决策不是执行，排队是对的
- 具体并行形（如「主语言档定稿后，其余语种文件写面不相交、逐语并行」）由**项目适配节**记载，不污染通用 skill

**fan-out 契约**（子 agent 只做分配面，机制类命令全线归主线；设计 v5·批 2 待实测）：

- 子 agent 不新增 key / 命名 / 接口语义——产物只许来自真源拉取或主线定稿的基准（如词汇表），缺口上报主线裁决
- 收口命令（生成器 / 门禁闸 / 全量测试）一律主线跑——子 agent 各自跑闸会互相污染结果
- 子 agent 报告 ≠ 验收——主线抽查质检后才算数（实证坑卡在册）

**长批执行的会话与台账**（批 1 实测 2026-11：全天压缩 20 次、摘要失真返工 1 起、进度被迫追问 3 次）：

- 任务边界必换新会话（收尾落盘→清上下文→下任务读盘接续）；同任务压缩 3-5 次后主动落盘重开优于继续压；测试红着 / 半成品未落盘不换
- 进度台账（如 STATUS.md）是唯一进度真相源——完成状态禁只发对话（会被压缩吞）；任务边界主动发一句话简报
- 摄入纪律：考古结论当场落清单 / 词汇表、后续引文档不重读源；大文件节读（offset/limit）；写后不回读整文件
