## 4 对「属实项」的修法升级(比外审原方案更优的部分)

### A2 —— 收窄为「只接最小集」+ 两个外审未覆盖的配套点

1. **只 @import NAVIGATION.md 一个**(3.1KB)。MAINTENANCE(4.5KB)不常驻:触发即更新靠编辑时纪律、收尾自检由 A3 的 Stop hook 承担,NAVIGATION 指过去即可。patterns/business-rules/INVARIANTS 本就设计为涉域前 Read,@import 全家是反模式。与外审自己说的「常驻成本计入 §4.8」自洽——接线时就只接最小集,而非接线后算账
2. 外审漏改一处:[记忆库体系.md:37-43](../进阶/记忆库体系.md#L37-L43)「会话开始时加载」**示例块自己也没用 @ 语法**,须同步修
3. NAVIGATION 模板满是 `<common-widget-dir>` 占位符,原样 @import 每会话拖一屏占位垃圾——接线应与 init 联动裁剪(与支持矩阵三段式同批);并处理「小项目不用记忆库」([记忆库体系.md:5](../进阶/记忆库体系.md#L5))与「install 无条件落 memory」的既有矛盾
4. 可选方案 B(机制更优):`.claude/rules/`(v2.0.64+)配 `paths: ["lib/**"]` frontmatter——编辑源码时才注入,恰是「触发即更新」的时机,零 CLAUDE.md 常驻。最小改动选 @import,机制最优选 rules+paths

### A3 —— 修法改写(原「一行 echo」无效)

exit 0 + JSON `{"hookSpecificOutput":{"hookEventName":"Stop","additionalContext":"…队列非空…"}}`(进 transcript 作为 hook feedback,模型可据此行动)。实现注意:① Stop 每个 turn 末都触发(非仅收尾),队列非空期间每 turn 提醒——接受之(漂移本该尽快清)或仅条数变化时提醒;② 与 async 写侧的竞态:读侧也走 flock 或容忍半行;③ additionalContext 无死循环风险(不需处理 `stop_hook_active`,那是 block 语义才需要)

### A1 —— test-self 补验的轻量实现

CI 不用装 Flutter:`actions/setup-dart` + `dart create` + `dart pub add dev:flutter_lints` + 拷模板 AO + `dart analyze`(flutter_lints 是纯 Dart 包,纯 dart 环境可解析 include;实测单次 analyze ~5s)。删 `cancelled_token_use` 时**保留意图注释**:「CancelToken 纪律无对应 analyzer 规则,落点 checklist 异步纪律节,custom_lint 二期候选」

### B1 —— 三档执行,默认取中档

① 删通用内容(零风险立省)→ ② 拆 references/ + 坑库随迁(官方 progressive disclosure 形态)→ ③ 坑库独立成 skill(触发面成本最高,等 B3 观测数据)。即把外审 §8.4 折中档提为**默认**而非备选。补充官方依据(外审未引):auto-compaction 后每 skill 只重附前 5000 tokens(39KB 会被截断,功能性损失);skill listing 中 description 截断 1536 字符(拆分后每个 description 须独立命中触发场景)

### B2 —— 官方依据 + 一个执行陷阱

官方建议 CLAUDE.md **<200 行**(硬阈值 4 MiB 跳过加载,远未触及)。执行陷阱:§十一搬独立文件**再 @import 挂回 = 不省 context**(官方明说导入启动即载入,「拆分只利组织不减 context」)——必须落 skill/README(不 import)才真省

### D3 —— 警告分级 + 代码级修复

安装/init 警告分两级:「deny-list 闸失效(python3 缺失)」vs「漂移队列静默失效(python3 在但无 fcntl)」;README「Windows 上 hook 静默失效」措辞同步更新。代码修复:pending-updates 条件导入——fcntl 缺失时降级为无锁 `O_APPEND` 单行追加(追加本身原子,竞态窗口远小于「完全不记」),Windows 从「装了白装」变「降级可用」(~5 行)

### E5 —— 补维护注

model 档位名随 Claude Code 版本演进(sonnet/opus/haiku/…),硬编码有过时风险;标注处加一行「档位名随当前可用模型更新」
