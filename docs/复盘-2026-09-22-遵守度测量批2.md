# 复盘 · 2026-09-22 遵守度测量批2（SessionEnd 事实账）

> 日期：2026-09-22 · scope：1.0.37 批2 交付全程（设计 → 实现 → 验证 → 消费工程野外跑）

## 事件经过

批1 探针（dry-run）证毕解析率 100% 后开工批2：SessionEnd hook 每会话落一行事实到账本。途中撞的坑与执法点发现，按发生序：

1. **Stop ≠ 会话结束**（设计级，代价最高）。初版设计把「收尾对账」挂在 Stop 上——真症状是 stop-reminder.py 头注自己写着「自然停轮后队列仍非空会再提醒一次」：**Stop 每个 assistant 回合都触发**，挂上去 = 每轮全量扫转录。需求方追问「确定？」一轮后自审抓到，职责拆分：记账落 SessionEnd（每会话终结一次）、提醒留 Stop。派单语义没记错，只是没在动笔前回读兄弟 hook 的契约注记——兄弟文件头注就是最便宜的活文档。

2. **版本号一夜两撞**（多会话纪律）。批2 原计划 1.0.34 → 提交前发现被「分发工程批」消费，改 1.0.35 → 实现中途又被「deny-list 双源批」消费，且该会话注释里已用 1.0.36 指代它未发布的骨架目录批。最终 sed 全量重编号到 1.0.37，并给对方会话发了逐文件改动面认领（多会话工作树里「谁改了这一行」必须问得出、答得起）。规则：**bump 前 `git log --oneline -3` + `grep '"version"' plugin.json` 双查，动共享文件前 status 对账**——版本占号冲突本身无害，有害的是带着旧号继续写注释。

3. **SessionEnd 的 1.5s 共享预算**。官方契约：SessionEnd 各 hook 默认共享 1.5 秒、per-hook timeout 可上调——若照抄兄弟 hook 不写 timeout，大转录会在写完账前被宿主 kill，且 kill 无声（fire-and-forget）。处置三件套：hooks.json 登记 `timeout: 30` + 内部 BUDGET_S 10s 时间闸到点截断带 `truncated:true` 落账（截断是事实≠零违反）+ test-self 上 **timeout≥15 契约锁**（防未来「优化」删键——被删即红，本轮做了负控实证：手工删 timeout 键喂看守，报红）。实测 4505 行转录 0.16s，预算余量约 190 倍。

4. **孪生语义闸当场逼出漏改**。help.md「hooks ×3」是 0.6.2 上的闸看守的，加第四只 hook 后全套跑红一条——**闸红了不是坏事**，是对外口径漂移的构造性防线在生效。这类「加东西必忘改清单」的债，闸替人记。

5. **自动模式分类器拦消费工程转录抽检**。首跑把样本拷进临时目录再打印字段，被拦「外项目会话数据」；改纯标量输出口径（只回计数与长度，正文零外显）复跑过闸。§一敏感数据红线的机检执行连自家验证也不例外——**验证件自己先过闸**，比事后解释便宜。

6. **坑⓪由假说转实证**。消费仓「13/13 派单无包」读数，先核版本送达态再定性——其宪法层版本戳=1.0.25，早于切片包契约（1.0.27），属**预期缺位非无视条款**。若账不带 plugin_ver 列，这组读数就会被读成违约证据。「无数≠零样本」「缺位≠违反」是同族病的两侧。

7. **断言数口径的教训（自纠）**。改 test-self 环境守卫注释时按「47→48」写死了预期，实跑 50/0——外部评审批同窗在飞 +2 条。注释遂改为「计数以实跑为准」。写死的数会漂，跑出来的数不会。

## 值得沉淀的候选

SessionEnd 事件契约四事实（默认共享 1.5s 预算可 per-hook 上调／输出 fire-and-forget 无人读 stdout／终结瞬间转录尾行可能未落盘需聚合侧勿定罪／resume 型会话同 sid 多次终结）——hook 开发者视角的 OS 级坑，装插件的宿主环境全平台适用。
**【待蒸馏】**：SessionEnd hook 默认与他人共享 1.5s 预算且输出无人读——重活（扫转录）须自带上调 timeout + 内部时间闸 + 截断入账，否则大样本被静默 kill 读成「零违反」。

Stop 每个 assistant 回合都触发、SessionEnd 才是会话终结——把「收尾」类职责挂 Stop = 每轮全量重扫；兄弟 hook 头注（「自然停轮后队列仍非空会再提醒一次」）就是这条语义的免费证据。执法点选址前先回读同事件面既有文件的契约注记。
**【待蒸馏】**：Claude Code 事件语义速记——Stop=每轮、SessionEnd=终结；「收尾对账 / 会话级记账」类职责只属 SessionEnd，挂 Stop 即每轮重演。

测量件隐私红线做成构造性而非纪律性：账本 schema 里就没有正文字段（只有计数/布尔与 ts/sid/reason 三短串），fixture 设「手输长句不得出现在账面」断言 + 真转录泄漏抽检——想泄都没有容器。
**【待蒸馏】**：观测件防泄漏优先做「字段级不存在」（schema 无正文容器 + 断言锁），而非「运行时不打印」——前者坏不了，后者每改必审。
