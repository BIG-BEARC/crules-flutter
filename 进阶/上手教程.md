# 上手教程：15 分钟走完第一次闭环

> **本篇给谁**：刚装完 crules-flutter、还没实际跑过一轮的用户。用一个虚构小需求走完「需求 Gate → 方案 Gate → 实施 → review → 沉淀」全程，让你知道**哪些环节 AI 会主动拦你、哪些全自动、你每步要回什么**。
> **对话均为示意**（按当前规则文案编写），实际措辞以会话为准；读完不必记忆——真实会话里 AI 会按规则主动走位，你只需要认得它在干什么。
> 已装未跑 `/crules-flutter:init` 的工程先跑 init（含必填三处引导），本篇从装好后讲起。

---

## 0. 装完后你身边多了什么

| 东西 | 什么时候出现 |
|---|---|
| hooks（deny-list / 漂移队列 / 收尾提醒） | 静默生效，只有触发时才可见 |
| 7 个角色 agent | 自动挂载，写 UI 时 AI 自己用 frontend，不用你点 |
| 根 CLAUDE.md 双 Gate | 你提非平凡需求时，AI 会**先停下来问你** |
| checklist.md + reviewer | 交付收尾时 AI 主动走 review |
| 记忆库（`.claude/memory/`） | 会话收尾时 Stop hook 提醒你补索引 |

一句话心智模型：**你负责裁决，AI 负责执行和自证**。下面走一遍。

---

## 1. 提需求（你会先被拦一次）

你对 AI 说：

> 给设置页加一个「清除缓存」按钮，显示当前缓存大小，点击后清空并刷新。

这不是单字段文案改动，AI 会触发**需求 Gate**——它不会直接动手，而是先回你一段确认（示意）：

> **需求确认（需求 Gate）**
> ① 要解决的问题：缓存无入口可清，占用渐大
> ② 预期结果：设置页新增按钮，显示缓存大小，点击清空后刷新
> ③ 范围：仅设置页 UI + 缓存统计/清理逻辑；不含其他页
> ④ 约束：缓存大小计算沿用现有工具类（若无可新建）
> ⑤ 验收标准：显示大小与实际一致；清空后显示归零；无崩溃
> ⑥ 待确认：清空是否需要二次确认弹窗？
>
> 回复「确认」或直接回答待确认项。

你回：「要二次确认，其他确认」。**这就是需求 Gate 的全部交互**——你不需要知道流程叫什么，被问了就答。

## 2. 方案确认（第二次拦）

AI 读过相关代码后，给**方案 Gate**（示意）：

> **实施方案（方案 Gate）**
> ① 受影响文件：`settings_page.dart`、新增 `cache_service.dart`
> ② 修改位置：设置页列表末尾追加 tile；新文件放 `lib/services/`
> ③ 当前实现：设置页无缓存相关项；无既有缓存工具
> ④ 修改方式：tile 显示 `CacheService.size()`；点击弹二次确认后 `clear()` 并 setState
> ⑤ 影响：纯新增，无既有行为变化
> ⑥ 预期效果：见需求
> ⑦ 风险：缓存大小计算遍历目录，放 Isolate 防卡顿；回退 = 删两个改动点
> 验证：`flutter analyze` 零 warning + 单测 size/clear + 模拟器手测
>
> 确认后我开始实施。

你回「可以」。AI 开始写码。**从此到交付前你不需要再说任何话**。

## 3. 实施与收尾（全自动，最后给你一份汇报）

AI 写完代码后自动走收尾时序：机械验证（analyze / test）→ 派 **reviewer**（只读 agent）按 `checklist.md` 逐条审 → 修复 → 复验，然后给你交付汇报（示意）：

> **交付汇报**
> - 改动：`settings_page.dart`（+38 行）、新增 `cache_service.dart`（含单测）
> - 验证：`flutter analyze` 零 warning；单测 6/6 绿；模拟器手测通过（目标环境证据）
> - **Review 结论**：reviewer 报 2 条——①清空后未刷新大小显示（已修复）；②`catch (_) {}` 吞异常（已改为记录后降级）。复验：重跑单测 + 重审修复点
> - **沉淀候选**：1 条已暂存复盘（【待蒸馏】：大目录遍历需 Isolate 隔离）
> - Git：未提交，等你指令

你对 review 发现逐条表态（「都同意」），然后说「commit」。AI 只本地提交，**不推送**；你说「push」才推。

## 4. 会话结束（Stop hook 提醒你）

你结束会话时，若漂移队列非空（本轮改了源文件但索引没跟上），会收到一条注入提醒（示意）：

> [crules-flutter] 记忆库漂移队列非空（2 条）：settings_page.dart、cache_service.dart——对应索引补了吗？补完清空 `.pending-updates`。

按提醒补一眼 NAVIGATION / 索引即可。这是收尾兜底，**平时写代码时 AI 顺手更新，多数时候轮不到它出场**。

## 5. 第一次 `/distill`（交付上线后，你主动发起）

上线稳定后，你说 `/crules-flutter:distill --scope 清除缓存`。AI 清点复盘里的【待蒸馏】候选，先过五问过滤，然后**逐组给你看落盘原文**（示意）：

> **候选组 1/1**（目的地：`patterns.md` · 描述性，直写）
> `lib/utils/` 存在大目录遍历工具（2 处实证：`cache_service.dart:22`、`log_export.dart:41`，2026-09-09），新遍历需求先复用。
>
> 采纳 / 改写后采纳 / 丢弃 / 降级到复盘？

你裁决后 AI 局部 Edit 落盘。**闸类条目（业务规则 / INVARIANTS / 坑卡）永远不会不经你裁决就进 memory**——这就是「制度层」和「随手层」的分界。

---

## 6. 你还会遇到的三件事

- **危险命令被硬拦**：AI 想跑 `git push --force` 之类会被 hook 直接 block，提示「请需求方人工执行，不要尝试绕过」——**这是特性**。需要强推时你自己在终端跑（建议 `--force-with-lease`）。
- **新依赖被问**：AI 引任何新包前会先说明理由/影响/回退并等你确认，还会先查平台坑库。
- **后台 agent 完成**：AI 会主动贴 `git status` + `git diff` 给你审，而不是只转述 agent 的自报——diff 是后台模式下你审阅的唯一入口。
