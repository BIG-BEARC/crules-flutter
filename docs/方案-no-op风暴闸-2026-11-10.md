# no-op 风暴闸（no-op-gate）

> 状态：已确认 v2（2026-11-10 需求方四裁＋评审 12 发现全数处置；待实施批 1.3.6）· 日期 2026-11-10 · 关联：super_printer 任务耗时/花费诊断（2026-11-10，`crules-flutter:diagnose`）、[评审-plan-no-op风暴闸-2026-11-10.md](评审-plan-no-op风暴闸-2026-11-10.md) · 面向对象：crules-flutter 1.3.6 候选批

## 1 目标与范围

**要解决**：会话（尤其子代理）在等待后台任务/事件唤醒时连发裸 no-op 命令（`true`、`:`），每次都是一次全上下文 API 往返。2026-11-10 实测单例：super_printer T2 子代理 44 分钟连发 446 次 `true`（grep 精确复核），均载 ~118.6K 上下文，仅此一项 ≈52.8M cache_read（占该任务全程 165.7M 的 1/3），换到的输出全部是 exit 0。且模型**已知正确做法仍不改变行为**——转录 thinking 原文（agent-a3202cc0.jsonl L149，12:49:55）：

> "The right move: stop issuing no-ops and simply end my turn WITHOUT the final handback — the system will re-invoke me on monitor events / task completion. … So yes, I can end the turn with a status message and I'll be woken by events. That's the designed flow."

同一消息流内 168ms 后（L151，04:49:56.228→.396）它输出「I'll pause here」纯文本收尾后**继续**发出 `true`「Yield until monitor events arrive」，此后每 4–6 秒一次×446。**结论：文案说教不可承重，须机械闸；且宿主对子代理的「不要结束回合（＝最终回复＝子代理终止）」指令使「结束回合等唤醒」在子代理面不可执行（SA L92/L98/L124），block 指引必须按面分叉并消解该冲突（D4）。**

**不做什么**：
- 不拦复合命令（`true && x`、`x || true`、脚本内 no-op——合法形态面广）；
- 不拦单条 `sleep` 等待（可接受等待姿势，事故中仅 2 次）；
- **绕行形态明知不堵**（诚实边界，照 deny-list 头注体例）：`/usr/bin/true`、`command true`、`env true`、`FOO=bar true`、`:` 带参注释等均可绕计数——止损闸只保已知形态，绕行升级留给观察窗数据；
- 不改压缩闸语义（R1 已裁续期，2026-11-10）；
- 不动消费侧 superpowers 栈／SDD brief 模板（归属消费工程）；
- 不处理 super_printer 全量套件挂死（flutter 工具链＋同机多工程测试并发，另案）。

**老行为变更**：Bash 裸 no-op 在滑动窗口内超阈后被 deny、持续后升级人裁弹窗——此前无任何拦截。

**盲区三扫**：异常态——①状态档损坏→fail-open 放行（止损闸方向；与 deny-list 安全闸 fail-closed 相反，刻意）；②**无记忆库根→静默不介入**（需求方四裁之三，house 同款：compact-gate 先例 `find_project_root` 为空即 exit 0；代价＝无根工程内零防护，入档声明）；历史存量——不涉（新机制无存量迁移）；平台兼容——macOS/Linux python3 主路径，Windows PowerShell 不挂（裸 no-op 风暴形态在 PS 下罕见，非目标）。

## 4 目标方案

**候选对比（Q1 已裁 A；留档备查）**：

| 候选 | 拦截时效 | deny-list 可靠性风险 | 每 Bash 开销 | 结论 |
|---|---|---|---|---|
| **A 独立 no-op-gate.py（PreToolUse 第二条）** | 实时 deny＋ask 升级 | 零（不动 deny-list） | +1 次 python spawn（≈50–150ms 本地，无网络无 token） | **已裁（四裁之一）** |
| B 并入 deny-list.py 第二检查段 | 实时 | 有：状态 I/O 引入 deny 故障面 | 零新增 spawn | 否 |
| C PostToolUse 事后记账不拦 | 无拦截 | 零 | 同 A | R1 证伪退路 |

**规则表（A 案 v2）**：

| 项 | 值 |
|---|---|
| 匹配 | 命令剥首尾空白＋注释后**整串等于** `true` 或 `:`（等价 `^\s*(true\|:)(\s*#.*)?$`）；其余一律不计 |
| 窗口/阈值 | 300s 内同 sid 计数达 15 后**第 16 发起 deny**；常量置顶可调（Q2 默认随批） |
| deny 出口 | JSON `hookSpecificOutput.permissionDecision:"deny"` ＋ `permissionDecisionReason` ＋ **exit 0**（D9；禁 exit 2） |
| ask 升级 | 同窗 deny 计 ≥5 次仍在发 → `permissionDecision:"ask"` ＋人面向 reason（D8）；窗口内后续每次均 ask |
| 记账 | per-sid 状态文件（窗口计数、修剪、孤儿扫落此，复用 `sanitize_sid`）；共享 `ledger.jsonl` **只追加**：每次命中一行（含 cmd 原文与 deny/ask 位），零重写 |
| 清扫 | 状态文件写入时自修剪超窗两倍旧键；启动扫 >7 天孤儿状态档（compact-gate 孤儿清扫同款，对象＝状态档**非台账**） |
| fail-open | 状态档/台账读写任何异常→本次放行＋stderr |
| hooks.json 参数 | matcher Bash；`async: false` 显式；`timeout` 显式 10s；`python3 … \|\| python …` 兜底链同款（JSON+exit 0 契约下安全）；双条同 matcher 执行序：先 deny-list 后本闸（裸 true 永不进 deny/warn 面；多 hook 决策聚合 deny 优先——官方口径，对本闸无实质影响） |

**deny 消息（模型面向候选原文，Q3 默认随批）**：

> [no-op-gate] 检测到 no-op 风暴（300s 内 ≥15 次裸 true/:）。每次无操作命令＝一次全上下文 API 往返。改用其一：①**单条带超时的等待命令**（如 `sleep 30 && tail -c 500 <输出档>` 或 `until <条件>; do sleep 5; done`，一次调用等到事件）；②主线程可直接结束回合等事件唤醒。**子代理注意**：宿主「不要结束回合」指勿以最终回复收尾（那会终止你），中途等待用①即可。不要再发裸 no-op。

**ask 消息（人面向候选原文）**：

> [no-op-gate·人裁] 本会话 no-op 风暴已 deny 5 次仍在持续（模型在等待后台事件时空转，每轮≈全上下文 API 往返）。放行本次／拒绝并让它换姿势／直接中断会话，由你定。

**状态档与台账（jsonl 行样例）**：

```json
{"schema": 1, "ts": "2026-11-10T13:05:45+0800", "sid": "<会话id>", "plugin_ver": "1.3.6", "hook": "no-op-gate", "event": "hit", "cmd": "true", "decision": "deny"}
```

（`decision` ∈ allow/deny/ask；per-sid 状态文件 schema 照 compact-gate 状态件体例，实现批定稿。）

## 5 影响面

- **用户/会话**：所有装本 plugin 的会话每次 Bash 调用多一次 python spawn（本地 ≈50–150ms；对照事故中被防下的 44 分钟/52.8M，量级可忽略）；风暴时模型收 deny 指引，持续 5 次后人收 ask 弹窗。
- **已有功能**：deny-list、compact-gate 及其余五件零改动。
- **平台矩阵**：macOS ✅／Linux ✅（python3）；Windows PowerShell 不挂（非目标，§1）；**无 `.claude/memory` 根的工程＝静默不介入**（四裁之三）。
- **复用方回归面**：四消费工程经 directory marketplace 同步即生效（源＝本仓工作树——收口前提醒需求方勿 update，收口后提醒择机 update）。
- **涉依赖/构建/CI**：不涉。
