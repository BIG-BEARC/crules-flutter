# 弹窗树：嵌套弹层的强制遍历

> 本文件为 parity-rewrite skill 机制条文，SKILL.md 执行到〔第 0 步第 6 条、铁律 10、Phase 1 Step 3、Phase 2 定稿 = Human Gate〕时 Read 本文件。

**病灶**（复刻实战采证，需求方确认）：二三级弹窗经常不被读——Step 3/4 遍历对象是「page → 下一个功能页面」，弹窗/面板/抽屉是 modal 不是 page，在枚举模型里没有位置，AI 自然不会去读；漏网的弹窗行为在验收或上线后暴露，即返工。

**机制**：Phase 1 Step 3/4 的遍历对象从 page 清单扩为**「页面-弹窗树」**，深度不限：

## 出口闭包规则

入口机械化——不靠"看代码想起来"，反查弹出口调用点。**起点清单**：`showDialog` / `showModalBottomSheet` / `showGeneralDialog` / `showMenu` / Cupertino 系弹窗 / 自定义 overlay / 面板展开态 / 路由 push 的弹层页；**栈形制由第 0 步按项目实际扩展**（零项目值不破）。关键堵漏：**若弹出口命中项目封装（wrapper），必须识别封装体 → 把封装体的全部调用点并入出口集 → 迭代至集合不再增长**——只 grep 原生 API 会在"最大弹出面走 wrapper"的工程上当场复发漏读。**wrapper 机械判据**（防"算不算封装"又成交付语义自判）：函数体内含原生出口**或已认定 wrapper** 调用的项目自有函数/方法，即并入，按 grep 函数体递归判定，不按命名风格或观感。每个出口 = 树的一个节点

## 双侧出口集，各查各的

树枚举反查的是**参照实现侧**的闭包（其栈形制记入适配节「参照实现弹出口形制清单」，第 0 步现场查得）；「防外溢闸」的复用面 / 引用方回归（[boundary-asset.md](boundary-asset.md)）按**目标工程侧**闭包计。两侧"查过于:___"分开留痕。事件总线式二阶间接（非方法调用直链）机械不可达，显式归返工账兜底（[rework-ledger.md](rework-ledger.md)）——事件源形制清单是启发式非完备，剩余漏网归返工账根因「枚举漏」回灌

## 隐性事件源同查

树节点除"看得见按钮的弹层"外，还须登记**事件驱动弹出**——socket/推送消息触发的弹窗、扫码/键盘等外设事件、全局 redirect/guard。反查形制：全局监听注册点 + 消息路由表；核不到的工程显式记"本栈无此类源（查过于:___）"，不许默认无

## 父子链与节点登记

每节点登记**父子链**（二级弹窗 ← 一级弹窗哪个按钮/条件唤起）与自己的四列：功能×分支态、文案点、视觉关键值、对照断言（模板〔页面-弹窗树清单〕树化；〔下游页面清单〕保留为**页面间下游跳转**清单，弹层进树、页面跳转进〔下游页面清单〕，两节不重不漏）

## 完整性单一判据

**「本批作用域内出口闭包完整」= 可定稿**——批次分片合法，但作用域外的出口/子树必须在清单显式登记为「待后续批次」行（算已填，不算空格）。**作用域怎么划**（防定稿先于分片的时序矛盾）：作用域=本任务 Phase 3 分批的**首批「改哪里」范围 + 适配节预划模块边界**，在 **Phase 1 开始前划定并登记在清单头部**（不是定稿时才有）；后续批次各自定稿前重划。**本判据为全篇唯一表述**——SKILL.md 铁律 10 与 Phase 2 定稿闸均引此处，各处不得另立表述

## 跨批销账

「分片合法」的正当性前提：任一后批定稿包必须**出示前批全部「待后续批次」行的销账核对**（逐条：已枚举→转正式行 / 确属范围外→新登记归后续批），任务终收口（Phase 5）时核销账率——不许烂尾

## 树上空格一眼可见

弹窗漏读从"AI 忘了"变成"清单有一行没填"——可核对、可问责
