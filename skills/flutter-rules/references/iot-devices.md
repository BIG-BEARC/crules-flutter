## 通用铁律（自 backend 角色卡迁入，原文全量）

- 写入与读取要有应答确认机制，不要「发了就当成功」
- 分帧 / MTU 安全值要保守，不踩协议边界
- 先订阅再写入，否则通知丢失
- 不要在长生命周期 stream 上用一次性消费操作（如 `firstWhere`）——长流持续监听，短流才一次性
- 重连必须 dispose 旧上下文创建新的，不复用旧订阅
- 协议文档不可全信，**以实际设备字节日志为准**
- 长操作要有超时和断连处理，不阻塞事件循环

## 外设类（按通信方式分节）

### 蓝牙（BLE 电子秤等）

扫描 / 配对 / MTU 谈判 / 重连退避。【待项目沉淀】

### 串口 RS232（电子秤 / 部分打印机）

帧协议解析、粘包拆包。【待项目沉淀】

### USB（扫码枪 HID 模式 / USB 打印机 / 钱箱 RJ11 经打印机触发）

设备枚举与权限、HID 键盘流与广播模式差异。【待项目沉淀——扫码全角半角坑实证见下】

### 网口（打印机）

漏打保护：连发间隔保护（兼容模式）。【实证：saas-cashier `173e731c1`（网口打印机兼容模式——漏打方案 3.1 连发间隔保护）】

### 打印专项

ESC/POS 指令集；字形缺失（维语 / 阿拉伯语 / 泰语等设备无法渲染的 Unicode）用文字渲染为图兜底（与坑卡「系统字体回退不可信」联动）。【实证：saas-cashier `aaa9995fd`（ParagraphBuilder 文字转图渲染器）】

### 扫码专项

扫码枪 HID 键盘流 vs 广播模式；扫码注入字符串的全角半角归一。【实证：saas-cashier `db82458e5`（支付 / 券核销 / 团购扫码键盘全角切半角）】

### 钱箱

RJ11 经打印机指令触发；触发失败的兜底与提示。【待项目沉淀】

## 多屏类

### 副屏 / 数字客显

Flutter 多 window（`View` / Display API）或平台通道投屏；主副屏生命周期与分辨率差异。【待项目沉淀】

## 独立 App 类（指针节）

### KDS / 叫号大屏

另一端是**独立 app**（另一台设备），走网络同步协议（WebSocket / 轮询）——归 backend 网络域，不属本机设备通信；设备侧坑（大屏分辨率 / 常亮 / 开机自启）住项目 memory 坑库。
