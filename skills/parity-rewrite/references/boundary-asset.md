# 复用边界与资产盘点：双向防自作主张

> 本文件为 parity-rewrite skill 机制条文，SKILL.md 执行到〔第 0 步第 4、6 条、铁律 11、Phase 1 Step 3、Phase 3、Phase 4〕时 Read 本文件。

同一病根的两面：动手前没做过**项目资产盘点**，AI 眼里只有参照实现与目标模块，中间"工程已有什么"是空白。该守的界没守（伸手动共享件）是一面，该用的件没用（公共空间有封装仍自写）是另一面。**双向闸**：

## 防外溢闸

**病形**：改多处共用的控件，波及未知引用方。

**机制**：**默认=副本隔离，动共享=Human Gate**：复刻时共享件行为不满足，默认落点是目标模块内**私有副本/参数化扩展**；确需改共享件，先上报**引用方影响清单**、经需求方裁决才动。裁决通过后，**所有引用方涉及的功能必须测试覆盖且全绿**才算完——回归面从"目标模块"扩到"全部引用方"，范围依据即 Phase 1 登记的引用方名单（凡动共享必报，不设模块内外豁免）。**「默认」只是上报时的建议形态，最终裁决永远归需求方——AI 不得把"按默认走"当成"已获裁决"**。**「动了共享」按下述机械判据自判，不按语义**：本批 diff 触及共享目录、或触及复用面名单内文件 = 动共享（**加可选参数、改默认值、改内部实现均算**，"我只是扩展没改行为"不构成豁免）；判据命中而裁决记录缺失，Phase 4 直接判未达标。

## 防重造闸

**病形**：公共空间已有 titlebar / 下拉框等封装，AI 视而不自写，review 时替换返工。

**机制**：**资产核对只许两种书面结论**：「复用 X」或「核对过 X/Y/Z 不满足，原因：___」。**"没找到"必须写成"翻了哪、为什么不适用"**，不许沉默略过。Phase 4 对偶检查：批次新建了公共形态件（新弹窗封装/工具函数），反查工程是否已有同能力件，有即返工项。

## 复用面登记（Phase 1 强制）

树/清单每节点多一列「被谁复用」= 全部引用方**计数 + 名单（区分模块内/模块外）**，"共享"不许当形容词用——名单同时是「防外溢闸」的裁决面与引用方回归范围的依据。**注意两源分列**：功能×分支态×文案×断言诸列枚举的是**参照实现**，复用面列登记的是**目标工程**——模板列头显式标源，防执行会话迷路。

## 资产底账：优先复用项目已有索引，派生脚本只是兜底

某类工程早已建有组件索引并立了"触发即更新"维护纪律，再建一套派生=第三套重复建设：

- **第 0 步动作**：沿链查找项目**已有的**组件/公共资产索引（适配节给指针）→ 有则**读索引 + 核对其"最后更新"时间戳**，过旧才要求刷新（刷新走项目自己的维护流程）；无索引的工程才派生——脚本放**项目纪律规定的脚本目录**（工程有「脚本必须集中放置」类规则时遵项目规则，本方案不指定路径），扫公共组件目录抽「名称+路径、用途、全工程引用计数」产 markdown
- 资产核对结论的**稳定锚 = 组件名 + 路径**（行号随刷新漂移，跨批留账会失效）；例「复用 `<组件文件路径>`（`组件类名`，索引载明已 `N` 处引用）」
- 再生产物若入 git 会造脏区、与"禁自动提交"相撞：由项目侧决定 gitignore 或纳入其既有刷新流——skill 只读产物、不代管提交
- **归位**：索引指针/刷新流 = 项目侧，适配节记载；「第 0 步读底账+核时间戳、结论引用稳定锚」= 通用动作进 SKILL.md——零项目值纪律不破
