# 记忆库体系

> **fork 声明**：本篇 fork 自 crules `v74-fork-base`，由 crules-flutter 独立演进。

> **启用条件**：项目大到需要代码索引 / 决策日志时，复制本篇 + 配套 `memory/` 目录（部署位 `.claude/memory/`）到项目的 `.claude/memory/`。小项目不用。
> 配套根规则：[`../CLAUDE.md`](../app/CLAUDE.md)。git 纳管政策（单一权威在 `memory/MAINTENANCE.md`「git 分层」节）：制度资产（`patterns.md` / `business-rules.md` / `INVARIANTS.md` / `decisions/`）**进 git** 团队共享，`indexes/` 与 `.pending-updates` 本机；crules 源仓库中 `memory/` 为模板，随仓库进 git 供分发。

---

## 目的

防止重复造轮子、保留架构决策、加速大项目检索。给 AI 一份「地图」，不用每次全库 grep。

## 文件结构

<!-- twin:mem-files -->
| 文件 / 目录 | 用途 | 加载时机 |
|---|---|---|
| `NAVIGATION.md` | 顶层导航地图，告诉 AI 去哪找东西 | 项目 `CLAUDE.md` 引用，每次会话隐式加载 |
| `MAINTENANCE.md` | 自动维护规则，AI 何时该更新本库 | 同上 |
| `patterns.md` | 项目特有代码模式 | 实现新功能前 Read |
| `business-rules.md` | 业务真实规则（业务实际怎么运转的事实） | 审查 / 方案评审涉域前 Read |
| `INVARIANTS.md` | 技术不变量（任何路径都必须成立） | 改约束密集模块前 Read |
| `reference-map.md` | 分域调研参考系（只存指针不存结论） | 涉成熟领域做方案前 Read |
| `platform-pitfalls.md` | 平台坑库（支持矩阵 + 结构化坑卡） | 引依赖 / 写平台代码 / 升级前 Read |
| `indexes/*.md` | 各核心目录的代码索引 | 在该目录工作前 Read |
| `decisions/YYYY-MM-DD-*.md` | 单次重要架构决策日志 | 涉及该模块改动时 Read |

## 会话开始时加载

项目 `CLAUDE.md` 中应声明：

```
.claude/memory/NAVIGATION.md   — 找东西的总入口
.claude/memory/MAINTENANCE.md  — 自动维护规则
.claude/memory/patterns.md     — 项目特有代码模式
.claude/memory/business-rules.md — 业务真实规则（涉域时读）
.claude/memory/INVARIANTS.md — 技术不变量（改硬约束模块前读）
```

---

## 实现新功能 / 添加文件前的强制流程

1. 在 `NAVIGATION.md` 找到对应索引，Read 一遍
2. 确认是否已有可复用组件 / 工具 / 抽象 —— **能用现成的绝不新建**
3. 不确定时反问需求方

## 写代码后必须更新（触发即更新）

下列操作完成后，**同一轮对话内**必须更新对应索引，不能拖到下次：

<!-- twin:mem-trigger -->
| 你做了什么 | 必须更新 |
|---|---|
| 新建 / 重命名 / 删除源代码文件 | 对应 `indexes/*.md` |
| 新增状态单元 / 业务逻辑模块 | 对应索引 |
| 新增可复用组件 | 组件索引 |
| 新增工具 / 扩展 / 混入 | 对应索引 |
| 新增 / 修改路由入口 | 路由索引 |
| 新增数据模型 / 枚举 / 配置 | 对应索引 |
| 新增数据层模块（仓储 / 拦截器） | 对应索引 |
| 新增协议命令 / 接口分组 | 对应索引 |
| 新增国际化分组 | i18n 索引（只记分组，不记单 Key） |
| 做出影响多模块的架构决策 | 新建 `decisions/YYYY-MM-DD-<slug>.md` |
| 发现并固化项目特有代码模式 | 追加到 `patterns.md` |
| 业务流程 / 接口契约变更（影响可达性判定） | `business-rules.md` 对应条目 |
| 硬技术约束 / 不变量变更（影响正确性） | `INVARIANTS.md` 对应条目 |

**判定标准**：如果改动会让「未来 AI 找东西的路径」发生变化，就必须更新。

## 索引文件格式

```markdown
# <模块名> 索引

> 最后更新：YYYY-MM-DD
> 源码位置：`path/to/dir/`

## 文件清单
| 文件 | 职责一句话 | 关键导出 / 关键类 |
|---|---|---|
| xxx.<ext> | ... | XxxService, XxxModel |

## 复用提示
- 如果你想做 X，优先用 / 扩展 yyy.<ext>
- 不要做 Z，因为 ......
```

**长度约束**：单个索引文件控制在 200 行内，超出说明粒度太粗，需要拆分。

## 维护时机优先级

1. **写代码时顺手** —— 加 / 删文件同时改索引（最高优先级）
2. **决策做出时** —— 立即开决策文件，不等「以后再写」
3. **全量刷新兜底** —— 长期未维护 / 批量重构后索引大面积失效时，对照 `NAVIGATION.md` 逐索引核对源码现状手动刷新
4. **会话结束前自检** —— 本轮改了源码但没更新索引，补一次；启用 plugin 时看 `.claude/memory/.pending-updates` 漂移队列（PostToolUse 自动记录，非空即有索引待补，见 `memory/MAINTENANCE.md`（部署位 `.claude/memory/`）自检清单）

---

## 不维护原则

- **不写完整 API 文档** —— 那是源码和注释工具的事
- **不复制代码** —— 所有「实例代码」都引用源文件路径
- **不记生成文件** —— 自动生成的代码不入索引
- **不记 git 能查到的信息** —— 谁写的、什么时候写的，`git blame` / `git log` 自己查

## 权威正文单一（与规则文档分工）

记忆库**只放索引、决策、项目特有模式**，**不放规则正文**：

- 规则（红线、流程、提交）只在 [`../CLAUDE.md`](../app/CLAUDE.md) 及 `进阶/` 各篇有一份权威
- 记忆库引用规则时只链接，不复制——避免多个不一致版本
- 踩坑案例（如审查过判）记 `patterns.md` 或 `decisions/`，记「为什么 + 机制」，不记规则本身
- `business-rules.md` 记的是「业务事实」（业务实际怎么运转），是**事实记录**不是**规则指令**——不规约开发行为，与 `patterns.md` / `decisions/` 同属项目特有事实，**不违反**「不放规则正文」；规则指令（红线 / 流程 / 提交）仍在 `CLAUDE.md` / `进阶/`
- `INVARIANTS.md` 记的是「技术不变量」（任何路径都必须成立），也是**事实记录**——但属硬约束，每条配可执行检查（测试 / 断言），破坏即自动拦；与 `business-rules.md`（软约束，审查 Gate 拦）区分

**约束分治 4 类**（各有载体与检查，不一锅炖）：

| 类别 | 定义 | 载体 | 检查 |
|---|---|---|---|
| 不变量 invariant | 任何时刻任何路径都必须成立 | `INVARIANTS.md` | 测试 / 断言（硬拦） |
| 业务规则 business rule | 业务真实运转方式 | `business-rules.md` | 审查 Gate（软拦） |
| 决策 decision/ADR | 为什么选 X 不选 Y | `decisions/` | 提案前读 |
| 假设 assumption | 代码依赖的外部条件 | 常在外部契约 / 接口文档 | 契约测试 / mock |

> `assumption` 常在外部（接口文档 / 契约），不强制入记忆库；前三类在库内，共用本篇治理。
- 与 spec-kit 的分工：spec-kit 管 spec / constitution（需求规约），记忆库管代码索引 / 决策 / 项目特有模式——两者不重叠，spec 不入记忆库，索引不入 spec

### 与项目文档的分工

| 文档 | 进 git？（政策见 `memory/MAINTENANCE.md`「git 分层」） | 受众 | 粒度 | 更新频率 |
|---|---|---|---|---|
| 项目架构文档（如 `PROJECT-KNOWLEDGE.md`） | ✅ | 团队共享 | 架构详解、组件用法示例 | 模块变更时 |
| `.claude/memory/` 制度资产（patterns / business-rules / INVARIANTS / decisions） | ✅ 团队共享 | 团队 + AI | 业务事实、不变量、决策 | 写代码顺手 |
| `.claude/memory/` 生成物（indexes / .pending-updates） | ❌ 本机 | AI | 代码索引 | 写代码顺手 |

## 自检清单（每轮对话结束前）

- [ ] 本轮新建 / 删除 / 重命名了源文件吗？对应索引同步了吗？
- [ ] 本轮新增状态单元 / 组件 / 路由吗？索引有登记吗？
- [ ] 本轮做了影响后续编码的设计决策吗？有 decision 文件吗？
- [ ] 本轮是否出现「其实项目里已经有这个工具」的情况？要不要补到 `patterns.md`？
